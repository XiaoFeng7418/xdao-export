# v0.21.16：导出大串时不再把整份成品先拼在内存里

这一版不改任何按钮与选项，只改「内容怎么写到磁盘上」。成品与以前逐字节一致（有专门用例比对），
但图片多的大串导出时内存峰值降了一个数量级。

## 为什么

上一轮拿一个真实的公开长串（79 页、1486 楼、259 张图）把五种格式挨个跑了一遍，量到：

| 格式 | 成品 | 峰值内存 |
|---|---|---|
| HTML（图片内嵌） | 106.8 MB | 1393 MB |
| PDF | 101.9 MB | 1393 MB |

原因是导出器先把所有楼拼成一个巨大字符串，再套模板拼成整份文档，写盘时又编码一份——
三份大字符串加上图片缓存同时在内存里。内存只有 8 GB 的机器，遇到更长的串就可能直接失败。

## 这版做了什么

- HTML / PDF 改成「打开文件，一楼一楼写，最后换名」，内存里只留图片缓存与当前这一楼。
- 中途取消不会在导出目录里留下半份成品（先写 `.part`，成功才换成正式文件名）。
- 合并导出同样走流式。
- 成品逐字节不变：新增用例把 `build()` 的返回值与落盘文件做逐字节比对。

## 结果

同一个串（缓存已热）：

- HTML（图片内嵌）：峰值 1393 MB 降到 **118 MB**
- PDF：峰值 1393 MB 降到 **118 MB**，用时 278 秒降到 143 秒

## 升级建议

如果以前导出过图文长串、内存吃紧或中途失败过，这一版值得换。
