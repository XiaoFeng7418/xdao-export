# v0.5.2：写不进去的地方，现在就换地方

这一版没有新功能，只做一件事：**把"目录写不进去"这类问题处理得让人看得懂**。

## 为什么又要发一版

v0.5.1 放宽了写权限预检（探针写不动不再拦住导出），但随后发现两个新问题：

1. **缓存目录该换地方却没换。** 判断"这个目录能不能写"时只看目录自己这一层，
   而真实的缓存要往下再建一层（`<缓存目录>\pages\<串号>\`、`<缓存目录>\images\ab\`）。
   于是出现 `D:\X岛\.cache` 建得出来、`D:\X岛\.cache\pages` 却"拒绝访问"的情况 ——
   程序以为目录能用，就一直往撞墙的地方写，缓存等于白存。
2. **报错只说了一句 errno。** 界面上只有
   `PermissionError: [WinError 5] 拒绝访问。: 'D:\\X岛\\.cache\\pages'`，
   既没说该换哪个目录，也没说常见原因。

## 这一版改了什么

- **写权限探测往下探一层**：既试建探针文件、也试建一个临时子目录，任何一步失败都算
  "这个目录不能写"。这是 `can_write_dir()`，缓存目录、导出目录的兜底逻辑都用它。
  探测完会把探针文件与子目录都删掉，不留垃圾。
- **缓存目录真的会兜底了**：首选位置不能写时，自动改用
  `%LOCALAPPDATA%\xdao-export\.cache`，并在日志里说明"原目录为什么不能用、这次用哪个"。
- **写盘失败时的提示改成能照着做的**：会指出是哪个目录被拒绝、建议换到「文档」这类
  默认能写的位置、换完仍失败时提示去查安全软件（受控文件夹访问 / 勒索软件防护）白名单。
- **缓存没留下成果时会明说**：如果这次抓取的缓存一个字节都没写进去，日志里会写
  "这次抓取不会留下断点续传的成果"，避免你以为下次能接着抓。

## 如果你仍然看到"拒绝访问"

那说明目标目录**确实**不允许当前账户写。请按提示换一个目录（例如「文档」或桌面下
新建的文件夹）再试；如果换到哪儿都失败，请跑一次仓库里的 `诊断写入.ps1`，
它会打印每个候选目录能不能写、目录权限表、以及 Windows 的受控文件夹访问状态，
把这些内容发给维护者就能定位。

## 下载

- `xdao-export-v0.5.2-win64.zip`（推荐，也是唯一的附件）：**免安装包**，解压后双击
  `xdao-export.exe`；里面有 `诊断写入.ps1`，写不进去时用它定位。不做任何解压动作，
  中文路径与受限环境都能启动。
- 单文件版自 v0.5.1 起不再提供：PyInstaller 的单文件版在含中文的路径下会直接
  报 `Could not create temporary directory!`，属于打包器的限制，不是程序本身的问题。
