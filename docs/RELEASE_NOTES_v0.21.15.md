# v0.21.15：修「没标题的串导 EPUB 会失败」

修一个只在特定串上出现的失败：串没有标题（或标题就是「无标题」）时，导出 EPUB 每次都失败，日志里是 `NameError: name 'derive_filename' is not defined`。

## 为什么会这样

EPUB 的书名优先用串标题；没有标题时本该退回「用文件名推导」的结果。这一行在 v0.13.49 的一次代码整理里被带进来，但它用到的函数没跟着导入——于是兜底那条路一走到就报错。

绝大多数串都有标题，所以这条兜底平时根本走不到；单元测试里也没有空标题的 EPUB，于是它一直躺在那儿。这次拿一个真实的 79 页长串做端到端导出才撞出来。

## 这版做了什么

- 补上缺的那个导入（一行），行为和原本的设计一致：书名优先标题，没标题才用文件名推导。
- 新增 2 条用例：标题为空、标题为「无标题」各一条，断言电子书里的书名就是推导出来的名字。`tests/test_epub.py` 38 → 40 条。

## 顺带量到的数据

同一个 79 页、1486 楼、259 张图的串：

| 格式 | 产物 | 耗时 | 内存峰值 |
|---|---|---|---|
| HTML 图片内嵌 | 106.8 MB 单文件 | 251 秒 | 1.4 GB |
| HTML 图片存同名目录 | 1.0 MB + 79.4 MB 图目录 | 204 秒 | 18 MB |
| PDF | 101.9 MB | 278 秒 | 1.4 GB |
| EPUB | 158.6 MB | 220 秒 | 202 MB |

图多的串建议选「图片存到同名目录」：成品从上百 MB 掉到 1 MB，内存峰值也从 1.4 GB 掉到 18 MB。图片内嵌时内存大约是最终文件大小的十几倍，机器内存吃紧就会很难受。

## 升级建议

导出过 EPUB 且那个串没有标题——这一版能正常导出了。其它情况升不升都行。
