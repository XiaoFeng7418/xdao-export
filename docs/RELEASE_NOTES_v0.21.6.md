# v0.21.6：给登录窗后台线程补失败分支用例

这一版不改任何用户能看到的行为——只补测试，把「用浏览器登录」那个窗口背后失败时到底发生了什么钉进用例里。

## 为什么

「用浏览器登录」的后台线程 `BrowserLoginDialog._worker` 负责起浏览器、连调试端口、等登录。它每次失败都要在运行日志里说清两件事：开窗前普查看到了什么、每一扇候选窗各是什么死因；而失败时还得把那扇已经起来的窗收掉——真机 2026-10-18 那次「一次点击弹出好几扇窗」，成因之一就是这里没收干净。

这段逻辑此前没有直接用例。坏掉时的表现很隐蔽：日志里只剩一句「打开浏览器失败」，看不到普查结果，也看不出窗口有没有留在屏幕上。

## 这版做了什么

`tests/test_window.py` 70 → 76，新增六条用例覆盖：

1. 这个版本里缺少浏览器登录组件时的提示；
2. 找浏览器这一步抛异常（例如注册表读不出来）；
3. 一台 Edge / Chrome 都没装；
4. 用户在「找浏览器的功夫」里点了取消——不能再多开一个进程；
5. 浏览器启动失败——普查与每一扇的死因都要进队列、那扇窗必须被结束；
6. 取消正好落在启动过程中——同样必须把刚起来的窗收掉。

断言的重点是「失败要说话、窗口要收干净」：`census_note` 与 `attempt_notes` 必须进队列、`browser.stop()` 必须被调用、错误文案带原始死因、成功路径不误报。

## 读数

只跑三个界面测试文件时，`xdao/gui.py` 未覆盖行数 530 → 463，行覆盖率 79% → 85%。
