# v0.13.34：饼干明明在罐里，程序却读不到 —— 加第四读，并让程序自己报账

## 该下哪个附件

下载 **免安装包** `xdao-export-v0.13.34-win64.zip`（解压后双击 `xdao-export.exe`，不需要装
Python）。同一页还挂着一份 `xdao-export-v0.13.34-win64.zip.sha256` —— 那是给上面这个包核对
用的校验文件，不是程序，不用解压。

## 这一版修了什么

真机复验 v0.13.33（m36303/m36307）钉出了铁证：棕色横条认出来了、就在程序弹出的那个窗口里
登录成功、F12 的「应用程序 → Cookie」面板里 `userhash` 就摆在那个窗口的饼干罐里 —— 程序却
仍然报「浏览器里还是没有 userhash」。也就是说：**饼干在罐里，是程序读罐这一侧出的事**。
同时这一轮也证伪了上一版写进每一句话里的前提：登录成功时站点就**自动带上你当前的饼干**
（罐里当场就有 `userhash`），点「应用」只是**换一块**时才需要 —— 「光登录不算完」是错的。

- **读饼干加了第四读**。程序原来用调试协议读罐有三种读法（按页面地址读 / 整罐读 / 存储接口
  读），这一版再加一种：把**被盯标签页自己可见的 cookie** 直接问页面要一遍 —— 和 F12 完全
  同一个视角。四路并读、结果合并，任何一路读到都算拿到，专门兜「F12 看得见、程序看不见」
  这类读法盲区。
- **程序自己报账（读罐对账）**。拿不到饼干时，运行日志每轮补打一行「读罐对账：…」，把
  程序挂在哪一页、每种读法各自看到了哪些饼干名并排列出来 —— **只有名字，绝不写值**。
  哪一路读漏了一眼就能看出来；把这行截图发给维护者即可定位，不用再猜。
- **话术认错并全部改正**。横幅、等待状态、超时收尾、粘贴提醒、对话框、使用说明，全部改成
  真实机制：「登录成功站点就自动带上你当前的饼干，程序自己会拿到；要换一块才到『我的饼干』
  点一行『应用』」。

## 界面、导出格式、配置文件、命令行开关

布局和 0.13.33 一样，没有新增也没有改位置；变的是上面这些等待话术、横幅文字，和日志里

## 下载后核对一下

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.34-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.34-win64.zip.sha256
```

两行的字符串一样就是原件。
