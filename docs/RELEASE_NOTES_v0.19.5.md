# v0.19.5：发版时校验 Release 标题格式

这一版不改用户能看到的行为，只给「建 Release」这一步加一道格式闸。

## 为什么

GitHub 的版本列表按 Release 标题排。标题统一写成 `vX.Y.Z：一句话说明` 时，一眼能看出
每版干了什么；一旦有两条写成别的形状，夹在中间就很扎眼，而且标题只在发版那一步写定，
事后再改要手动去网页上改。

问题是这一步以前没有任何校验：`tools/make_release.py` 收到什么标题就建什么 Release。

## 这版做了什么

- 新增 `check_release_name(tag, name)`：要求标题以 `<tag>：` 开头、后面有一句说明；
  拦掉「把 `xdao-export vX.Y.Z` 整段粘进来」「冒号后为空」「标题里写免安装包」
  「标题里带括号补充说明」；
- `main()` 在调用任何接口之前先校验，不合格打印正确形状并退出码 2，一个请求都不发；
- `tests/test_make_release.py` 31 → 40：好标题 2 条、坏标题 6 条、`main()` 拒发 1 条。

## 影响

- 对导出、界面、命令行参数：**没有任何变化**；
- 对发版：标题写错会在本地被拦住，不再需要事后去网页改。

## 升级建议

普通使用不需要升级；自己按仓库流程发版的，这一版能省一次「发完发现标题不对」的返工。
