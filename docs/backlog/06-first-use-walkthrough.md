# 首次使用演练：从下载到拿到成品

演练日期：2026-11-15。范围：在干净配置（空的 `APPDATA` / `LOCALAPPDATA`）下，按一个
从没接触过这个工具的人会走的顺序把整个流程走一遍，记下每一步看到什么、卡在哪。

**这份报告只记录观察，不改任何代码与 README。** 卡点按严重程度分三级：

- **阻断**：这一步走不下去，必须绕道。
- **困惑**：能走下去，但界面/文档的说法让人当场不知道怎么选。
- **瑕疵**：不影响完成任务，只是不够体面。

## 二、拿到程序

README 的「下载（打包版）」段（`README.md:225` 起）写的是：打开 Releases 页面，下
`xdao-export-v0.22.0-win64.zip`（推荐）或 `.sha256`，解压后双击 `xdao-export.exe`，
并强调 exe 不能单独拷走、旁边必须有 `_internal`。

- 下载与解压这一步没有歧义。
- **瑕疵**：这个段没有一处提「Windows 可能弹 SmartScreen」。「未知发布者 / 已保护你的电脑」
  的说明只写在 `README.md:83` 起的「代码签名政策」一节里 —— 而那一节在文档靠前的位置，
  但下载段没有回头引用它。第一次用的人很可能在双击那一步被拦住，然后回到 README 里找原因。
  建议在下载段加一句「双击后如弹「Windows 已保护你的电脑」，点「更多信息 → 仍要运行」」。
- 仓库里没有 `docs/screenshot` 以外的界面图；首屏已有一张截图（阶段二加的），够用。

## 三、双击启动

- 实测：把包复制到带中文和空格的路径（`首次使用 中文路径\`）后 `Start-Process` 启动，
  **两次探针都没看到 `xdao-export.exe` 进程，也没有窗口**，且 `Start-Process` 之后
  PowerShell 会话挂到 120 秒超时才被转成后台作业。
- 同一台机器上源码版 `python main.py --selftest --offline` 完整跑通，说明不是程序自身的问题；
  这与仓库既有的「本机安全软件会拦未签名程序」基线一致（打包自检退 1 也是这个原因）。
- **结论：这一条未验证。** 原因：本机安全软件拦未签名 exe。建议在未装安全软件、或已把该
  目录加入白名单的机器上双击一次，确认中文路径 + 空格路径都能起来（`packaging/使用说明.txt:46`
  声称「中文目录下也能正常启动」）。

## 四、首次打开界面

干净配置下窗口 1060×760，界面元素：

- 顶栏：标题「X岛串导出」+ 副题「HTML · PDF · TXT · Markdown · EPUB ｜ 断点续传 ·
  图片缓存 · 更新监控」；右侧「登录 / 设置饼干」「设置」「监控串更新」「配色 light」
  「字号 标准」。
- 状态行：「◆ 未登录　登录后才能在受限版块里看帖；只看公开串可以不登录。」
- 左栏：① 输入串网址（多行框，提示「每行一个，可一次粘贴多个串」）；抓取范围（所有人发言 /
  只抓 PO 发言）；只看指定饼干 +「从串中挑选…」；最多页数、串号截止（下有小字解释
  「留空或 0 = 不限」）；导出格式（HTML 单文件）+ 图片（内嵌图片）；本地缓存、监控时弹通知
  两个勾选；② 导出目录，默认 `C:\Users\你\Documents\X岛备份`，旁边「更改…」，
  下方一行「缓存：…」与「清空缓存」「打开目录」；底部橙色「开始导出」+ 灰「重试失败项」。
- 右栏：运行日志（带「检查更新 / 自检 / 清空 / 保存…」四个按钮），首条日志是
  「就绪。填入串网址后点「开始导出」。」

**卡点 1（瑕疵，最小窗口）**：窗口拖到最小尺寸 940×680 时，「导出目录」卡片里的缓存行
（`缓存：1 个串 · 1 张图片 · 0.4 MB` 与右边两个按钮）被「开始导出」按钮盖住。

- 实测坐标（都是相对窗口原点）：940×680 下缓存行占 590–645，开始按钮占 592–629 —
  **直接重叠**；1060×760 下缓存行仍在 590–645，开始按钮下移到 672–709，不重叠。
- 原因不是文案太长（缓存文案 63 字符单行），而是布局层级：缓存行挂在左栏外层 frame 上，
  不在滚动区 `Canvas` 里（该 Canvas 的 `scrollregion` 是 `0 0 444 552`，`yview` 恒为
  `(0.0, 1.0)`，本来就没有可滚动的内容），所以按钮一压上来就永久看不见、也滚不到。
- 影响：小屏或习惯把窗口拉小的人看不到缓存占用，也就点不到「清空缓存」。不影响导出本身。

**卡点 2（困惑）**：`--selftest` 说「导出目录：还没选（首次导出时会让你选一个）」，但界面
已经预填了 `Documents\X岛备份`，第一次点「开始导出」**不会**弹选择框，直接用预填值。
两边说法不一致，会让人以为程序漏了一步。

## 五、登录

登录对话框（`xdao/gui.py:1064` 起）把四件事都说清楚了：浏览器登录会弹一个独立窗口、
用的是机器上的 Chrome / Edge（Firefox 不行）、登录成功后程序自己会读到饼干、程序看的那扇窗
底边有棕色横条写着窗口号。找不到浏览器时也有专门文案（「没找到 Edge 或 Chrome…也可以改用
「直接粘贴饼干登录」」）。**这一段没找到卡点。**

## 六、粘贴网址 → 开始导出（卡点 3，阻断）

- 实测：不登录、直接点「开始导出」→ 弹「提示 / 请先登录或设置饼干。」并**自动打开登录
  对话框**，导出不启动（`_exporting` 仍是 False，日志停在「就绪…」）。
- 代码在 `xdao/gui.py:5476-5479`：

  ```python
  if not self.settings.userhash:
      messagebox.showwarning("提示", "请先登录或设置饼干。")
      self.open_login()
      return
  ```

  这条从首个提交（`8659aa2`）起就在，不是新加的。
- 但它与三处说法互相矛盾：
  1. 同屏状态行写着「只看公开串可以不登录。」
  2. `packaging/使用说明.txt:56` 写「不登录也能用，但只能读到每个串的前 100 页。」
  3. 命令行版确实是这么做的：`python main.py <串号>` 只打印一行
     「提醒：未登录，只能读取每个串的前 100 页。用 --cookie 或先运行图形界面登录。」然后照常导出（实测成功）。
- 后果：只想导一个公开串的人，被要求必须先登录才能用图形界面 —— 而登录本身要开浏览器、
  输账号密码和验证码。这是整个流程里最劝退的一步，而且文档在骗人。
- 建议（三选一，都不大）：① 把这条拦住改成「提示 + 确认框」，用户点「仍然继续」就用游客
  身份导；② 保留拦截，但把 `使用说明.txt:56` 与状态行改成「图形界面需要先登录（公开串也
  可以登录后导）」；③ 只在「抓取范围 = 只抓 PO」或受限版块时才强制登录。

## 七、命令行导出

实测 `python main.py 50577215 -f txt -o <空目录> --max-pages 1`（干净配置）：

```
提醒：未登录，只能读取每个串的前 100 页。用 --cookie 或先运行图形界面登录。
    注意：这次只抓到第 1 页（这次要抓的范围比这长），剩下的页没有抓：可以用「抓取范围 → 指定页码」分批导出，或把页数上限调大后重跑。
导出目录：…
格式：txt（.txt）｜范围：all｜缓存：启用｜缓存目录：…
导出范围：最多 1 页；不按串号截止。
[1/1] 50577215
    正在获取第 1 页…
    <N> 楼 · 首次抓取
    正在生成 TXT 文件…
    完成：…\<串标题>.txt（0.0 MB）
    缺页/缺图的清单：…\导出报告-20261115-172340.txt
全部处理完毕：成功 1 / 1 个。
```

- 目录里最后有：成品 `.txt`、`导出报告-<日期>-<时间>.txt`、`xdao-export.log`、
  和 `.cache/`（页缓存 + 串状态）。**成品在哪个目录、叫什么名字，一行就说清了** —— 这一步体验最好。
- 缺页时自动写一份报告文件，内容是「这次有 1 个串没能完整导出 / 标题 / 成品 / 楼层 / 缺页
  原因 / 补抓提示」，用户不用回头看日志。

**卡点 4（困惑）**：串号写错（`python main.py abcdef`）时提示的是

```
串号截止把列表里的串全都挡住了，没有要导出的串。
截止是「抓到串号 None 为止（含它）」…
把 --until 改成更大的串号、或去掉这个开关后重试。
```

—— 用户根本没写 `--until`，被告知去改它；真正的原因是「abc 不是串号，被丢掉了」。
而且退出码是 **0**（`main.py:779` 的 `filter_until_thread_id` 拿到空列表就归因为「被截止
挡光」），脚本里跑会当成成功。

## 八、拿到成品

- 图形界面结束时弹窗写「成功导出 1 / 1 个串。文件在：<目录>」；有失败或没抓全时换成对应
  的警告框，也都带目录路径。
- 命令行最后一行是「全部处理完毕：成功 1 / 1 个。」，成品路径在每串的「完成：」行里。
- **这一段没找到卡点**：两种入口都明确说了文件在哪。

## 九、建议清单（按优先级）

1. **（阻断，改一处文案或加一次确认）** 图形界面「未登录不许导出」与文档/状态行/命令行
   的说法三处矛盾。要么允许游客导出，要么把文档与状态行改对。
2. **（困惑）** 串号写错时报「被串号截止挡住」，且退出码 0。应改成「没认出这些串号：abc」
   并返回 2（与其它参数错误一致）。
3. **（困惑）** `--selftest` 说导出目录「还没选」，界面却已经预填并且直接用。
4. **（瑕疵）** 最小窗口 940×680 下缓存行被「开始导出」按钮永久遮挡（不在滚动区内）。
5. **（瑕疵）** 下载段补一句 SmartScreen 的绕过方法，别让人在双击那一步卡住去翻文档。
6. **（未验证项）** 打包版在中文 + 空格路径下能否双击启动，需在放行未签名程序的机器上验证。

## 十、复现方式

```powershell
# 干净配置下截首屏
$env:APPDATA = "$env:TEMP\xdao-first"; $env:LOCALAPPDATA = $env:APPDATA
python -X utf8 tools\gui_shot.py --out $env:TEMP\first.png

# 不给登录时点「开始导出」
# （打桩 messagebox，直接调 App.start()）

# 首跑自检
python -X utf8 main.py --selftest --offline

# 输错串号
python -X utf8 main.py abcdef -f txt -o $env:TEMP\xdao-try; echo $LASTEXITCODE

# 命令行首次导出
python -X utf8 main.py 50577215 -f txt -o $env:TEMP\xdao-try2 --max-pages 1
```
