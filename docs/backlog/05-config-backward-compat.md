# 配置与模板的向后兼容

审计时间：2026-11-15。对象：v0.22.0 的 `xdao/settings.py`、`xdao/watcher.py`、
`xdao/exporters/_shared.py`。方法：用 `git show <tag>:xdao/settings.py` 把每个版本的
配置键抽出来逐版对比，再用临时目录里的假配置实跑 `AppSettings.load()` / `save()`，
模板则直接调 `render_filename()`。

结论先放这里：**从 v0.7.0 到 v0.22.0 没有一次破坏性改动**——36 个配置键只增不减、
没有一个改过名字，五个导出格式键从未变过，文件名模板的占位符一字未改。老配置文件
在新版本里能正常打开，老用户手写的模板也照旧生效。

下面是「宽松」到值得知道的地方，以及一处有名无实的字段。

## 一、配置键的演进

| 版本 | 键数 | 新增 |
| --- | --- | --- |
| v0.7.0 | 21 | 初始的一套 |
| v0.8.0 – v0.13.0 | 28 | PDF 纸张、方向、边距、边距毫米、缩放、背景、页码范围 |
| v0.15.0 – v0.16.0 | 32 | 最多页数、串号截止、导出字号、界面字号 |
| v0.19.0 | 33 | 成品已存在就跳过 |
| v0.21.0 | 34 | 合并导出 |
| v0.21.21 | 35 | 同时抓页数 |
| v0.22.0 | 36 | schema（迁移用的版本号） |

`tests/test_settings.py` 里的 `LEGACY_V070` 就是第一行那份 21 个键的完整快照，
它至今仍在断言「v0.7.0 的配置读出来等于内置默认值」。

## 二、缺键与多键

| 场景 | 实际行为 | 风险 |
| --- | --- | --- |
| 老配置缺新键 | 全部落内置默认值，不报错 | 无 |
| 配置里多了不认识的键 | `load()` 时不看，`save()` 之后**这些键消失** | 低 |
| `extra` 字段 | 原样读进、原样写回，但**全仓没有任何代码读它** | 低 |

`extra` 那一条值得说一句：它在 `xdao/settings.py:249` 读、`:298` 写，两处之外
没有任何引用。也就是说手工往 `extra` 里塞的东西会被保留、但不会生效；反过来，
把它当「插件配置区」用是不成立的。

## 三、写错的枚举值

| 字段 | 写了不认识的值 | 行为 |
| --- | --- | --- |
| `format_key` | `"docx"` / `"PDF"` / `"123"` | 配置里原样保留；导出时静默用 HTML |
| `format_key` | `123`（整数） | 变成字符串 `"123"`，同上 |
| `format_key` | 空串 | 读成 `"html"`（视为「没写」，不是「写错」） |
| `scope` | `"po_only"` | 原样保留；筛选时只认 `"po"`，**效果等于 all** |
| `image_mode` | `"magnify"` | 回落 `"embed"` |
| `theme` | `"neon"` | 回落 `"light"`（`theme_name`） |
| `pdf_paper` | `"a99"` | 回落 `"default"` |
| 数字键写成字符串 | `"30"` / `"0.5"` / `"4"` | 正常解析 |
| 整份都是错的类型 | 见下 | 全部落默认，不抛异常 |

`scope` 那条是最容易被忽略的：配置里存了 `po_only`，界面下拉框会显示成空，
而导出范围实际是「全部楼层」。这不算新引入的问题（v0.7.0 起就是这么判的），
但值得在界面上做个兜底——不认识的范围直接按 all 显示。

整份类型都错时的实测结果：`scope` 落 `all`、`image_mode` 落 `embed`、`theme_name`
落 `light`、`timeout` 落 `20.0`、`page_workers` 被夹到上限 `6`（超范围是夹取，
不是回默认——与 `normalize_page_workers` 的约定一致）。

## 四、文件名模板

| 写法 | 结果 |
| --- | --- |
| `{id}` | `50577215` |
| `{count}` | `1` |
| `{po}_{count}` | `POHASH_1` |
| `{title}` | 回退名（`title` 位取的是**清洗后的默认名**，不是原始标题） |
| `{id}-{date}` | `50577215-20261115` |
| `{{title}}` | 字面量 `{title}` |
| `{title!r}` | `'回退'` |
| `{}` / `{0}` / `{unknown}` / `{title` / `}{title` / 空串 | 一律静默回退到默认名 |

`render_filename` 用 `except (KeyError, IndexError, ValueError)` 兜住所有实测到的
错法，模板写错绝不会让导出失败。与 `git show v0.7.0:xdao/exporters/_shared.py`
逐字比对，这个函数从 v0.7.0 起**一个字都没改过**。

## 五、监控条目存盘

| 兼容点 | 行为 |
| --- | --- |
| 饼干列表字段改名 | `from_dict` 同时认 `hashes` 与 `include_hashes`；`to_dict` 只写 `hashes` |
| `image_mode: "folder"` | 打回 `"embed"`（监控不支持同名目录模式） |
| 进度类字段 | `state` / `last_check` / `last_error` / `last_export_path` / `exports` **不存盘**，换机器后从头开始 |
| 往返 | `to_dict()` → JSON → `from_dict()` 后所有存盘字段一致 |

进度不存盘是有意的：README 与发布说明都写过「监控不保存进度」，重开之后先补一次，
再按变化发通知。

## 六、建议

1. **`scope` 写错时在界面上按 all 显示**（低）：现在下拉框会空着，而行为是 all，
   两者不一致最容易让人误判。
2. **`format_key` 写错时提示一次**（低）：静默变 HTML 会让「我明明选了 PDF」变成
   一次困惑，但只在配置里出现不认识的格式键时提示即可。
3. **`extra` 要么用起来、要么删掉**（低）：现在只是原样搬运，留着容易让人以为
   它是个扩展点。
4. **给 `save()` 加上「保留不认识的键」**（低-中）：现在多出来的键会被静默丢弃，
   如果将来有外部脚本往配置里写自己的键，会被这个行为吃掉。

## 七、这次补的测试

新增 `tests/test_config_compat.py`（26 条），只钉当前行为、不改产品代码：

- 多出来的键在存盘时被丢、`extra` 被原样保留；
- `extra` 在源码里只有读写两处（防止将来有人以为它在生效）；
- 不认识的 `format_key` 三类写法都回退 HTML，空串读成 `html`，数字变字符串；
- 拼错的 `scope` 等于 all；
- `image_mode` / `theme_name` / `pdf_paper` 的坏值回落；
- 数字写成字符串仍能读；
- 整份类型都错也能起来；
- 五个模板占位符、六种坏模板的静默回退、双花括号与格式化修饰符；
- 监控条目的 `hashes` / `include_hashes` 双名、`folder` 被打回、JSON 往返；
- 五个导出格式键不变。

跑法：

```powershell
python -m pytest -q tests/test_config_compat.py
```

## 八、范围说明

本报告只读代码与配置、只新增测试文件，没有改动任何源码。报告里的「风险」列是
按「升级时会不会让人踩坑」估的，不是安全等级。已发布版本的配置行为一律不回改。
