## 这一版修了什么

「用浏览器登录」在真机上出现过一种卡死法：你在程序开出来的浏览器窗口里登录得好好的，
甚至拿同一块饼干在站里发串都发得出去，程序的对话框却一直说「还没有 userhash」，一路等
到超时。查下来是读饼干的那条路本身漏了：程序问浏览器要饼干时带了一串地址（站点根、饼干
页、当前页），浏览器只回「会发给这些地址」的那部分；而真机上 userhash 那块被这个过滤挡在
外面 —— 同一个浏览器按 F12 打开 Application 面板，Cookie 列表里它明明白白在。

这一版给读饼干补了第二读：**不按地址过滤、整罐问一遍**（浏览器不认整罐命令时自动退到
F12 面板走的那条存储读法），只留属于 X 岛域的、按（名字、域、路径）去重后并进原来那罐。
按地址那读照旧先跑，读到了就一次都不多问；只有它漏了才去问整罐。于是：

- 漏掉的 userhash 补得回来，登录这条路走得通；
- 补上的时候界面会写明一句「按地址读饼干漏了 userhash，是整罐读补上的（域=…、路径=…）」，
  这句话同时进运行日志 —— 下次再卡，截图里就查得到漏在哪一读；
- 「走 HTTP 领饼干」那条兜底路自动受益：它拿的是合并后的整罐。

顺带把一句会骗人的提示改准：以前罐里**有** userhash 但值的形状不像时，名单后面写的还是
「还没有 userhash」，和真的没有一模一样；现在会写「有 userhash 但值的形状不像（几个字符、
几个非 ASCII、几个百分号……）」—— 只说形状，不说值本身。

自检里「写不进去」的劝告也补了一类真机原因：以前只提 Windows 的「受控文件夹访问」，可真机
上还有另一种 —— 火绒、电脑管家一类安全软件只信「有签名」的程序，没签名的程序写用户目录会被
悄悄拒绝（别的程序写同一个目录却没事）。劝告现在把这种情况点名，并给出两条路：把程序目录加
进安全软件的信任区，或等签名版。

