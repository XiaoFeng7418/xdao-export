# v0.19.6：给请求层与一键升级里的守卫分支补用例

这一版只补内部用例，用户能看到的行为一点没变。

## 为什么

覆盖率体检（2026-10-25）里，`xdao/client.py` 的行覆盖是 80%，`xdao/updater.py` 是 87%。缺的那部分很集中：全是「出错时才走到」的分支——限流重试、服务端 500 带什么话回来、响应体超过上限、网络超时、升级时新目录搬不过去要不要把旧目录改回原名、目录被别的程序占住删不掉怎么办。

这类分支平时一次都跑不到，真出错时却又要求它说人话、还要求它别把现场弄坏。此前它们完全没有直接用例：改错一行，测试全绿，用户升级时才炸。

## 这版做了什么

`tests/test_client.py`（39 → 55）：

- 429 限流：第一次 429、重试后成功，退避被叫过一次；429 到底时报的是「请求过于频繁」，不是一个裸的状态码。
- 5xx：报「请求失败 503」并把响应体里的说明一起带出来。
- 响应体超过上限（`max_bytes`）时立刻失败，不把整包读进内存。
- `Content-Encoding: gzip` 的响应体自动解压，并把响应头小写化备用。
- 超时与域名解析失败分别报「请求超时」「网络错误」。
- 代理环境变量：`HTTPS_PROXY` / `https_proxy` 两种写法都认，值两端空白会去掉；`apply_config` 在代理没变时不重装 opener。
- `update_cdn_path`、`image_url`（图片 / 缩略图两种）、`_api_get_json` 遇到 HTML 错误页时报「非 JSON」、`jump_page_url` / `jump_page_message` 两种属性顺序。

`tests/test_updater.py`（42 → 60）：

- 打包版里「程序目录」取 exe 所在目录，启动器就在它旁边。
- 下载大小未知时写「大小未知」。
- 解压被占用时包装成一句人话，而不是抛 `OSError`。
- 备份目录删不掉时不误报（继续删别的）、父目录没了直接返回空。
- 进程号非正数、以及非 Windows 上 `os.kill` 的三种 errno 分别怎么判。
- 新目录搬不过去时把旧目录改回原名（回滚），现场不会停在「旧的没了、新的没来」。
- 只清自己的目录：`discard_staging`、`_retire_staging` 遇到别的目录一律不碰。
- 日志写不成也照样叫醒帮手（别为了留痕耽误正事）。
- `_remove_tree` 超时返回「没删掉」，让调用方改成留记号；帮手进程消失后，记号目录立刻清掉。

## 结果

- 用例总数 2328 → 2362（本机 2355 通过、7 项真机用例默认跳过）。
- 行覆盖：`xdao/client.py` 80% → 87%，`xdao/updater.py` 87% → 91%。
- 契约用例、全量用例都是绿的；打包、下载回核、免安装包内的 `--version` 与自检照旧。

## 升级建议

功能一模一样，不升级也不影响使用。愿意把测试覆盖当保险的，直接换这一版即可。
