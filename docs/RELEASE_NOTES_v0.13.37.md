# v0.13.37：僵尸窗先收掉，对账再报「接=哪扇窗」—— 两扇窗两个罐，一眼分开

## 该下哪个附件

下载 **免安装包** `xdao-export-v0.13.37-win64.zip`（解压后双击 `xdao-export.exe`，不需要装
Python）。同一页还挂着一份 `xdao-export-v0.13.37-win64.zip.sha256` —— 那是给上面这个包核对
用的校验文件，不是程序，不用解压。

## 这一版改什么

v0.13.36 上线后真机复验（m38110）把最后一层窗户纸捅破：那页「饼干列表」窗口 Ctrl+F5 硬
刷新都不弹回登录页 —— 它的进程罐里明明有一块有效 userhash；程序同一时刻的对账却写着
`页=1（只有登录页）`、整罐只有 PHPSESSID。**两边都是真的，因为它们是两扇浏览器进程**：
之前某一轮开的窗，端口文件（`DevToolsActivePort`）被后来哪一轮启动预删了；备用目录的名字
又带着当时进程的编号，本轮程序猜不到 —— 于是那扇旧窗对普查看起来彻底隐形：你看得见它、
程序接不上它，只好再开一扇新窗，两扇窗各拿各的饼干罐，谁也不认识谁。

这一版把「看不见」变成「点名处理」：

- **普查加进程侧点名**。开窗前除了问端口，还直接列出还在跑的 msedge/chrome 进程，认领
  **只属于程序自己**的资料目录（你平时上网的浏览器从头到尾不沾，这是铁律）：端口还答话的
  旧窗照常接上；端口失联的僵尸窗**先收掉**，普查句点名「进程侧探到 N 扇端口失联的旧窗口
  （××），已先收掉」。收掉之后，世界上重新只有一扇程序窗口、一个罐。
- **用持久目录时会明说**。这一轮落到程序自己存的浏览器资料目录
  （`%APPDATA%\xdao-export\browser-profile`）时，日志会写明：那份目录记得上次开窗口时打开
  过的页面，窗口里看到旧的「饼干列表」就是这么来的，跟你自己的浏览器无关；想回到全新状态，
  关掉所有程序开的登录窗口后把这个文件夹删掉即可（只动程序自己那份）。
- **对账行加「接=」**。`读罐对账` 那行再多一段 `接=端口N` —— 程序这一趟接的是哪一扇窗
  （调试端口号）同并报出。两扇窗的罐目录同名也一眼分开；照旧只有名字和号码，绝不写任何
  饼干值。

界面布局、导出格式、配置文件、命令行开关都没动。

## 登录不行的话，这一版怎么自救

1. 看运行日志两行：`开窗前普查：…` 和 `读罐对账：…接=端口N…`。普查收过僵尸窗、或对账
   的 `接=` 端口和你肉眼那扇窗对不上，就是窗口错位；新版会把它处理到只剩一扇。
2. 想回到全新状态：关掉所有程序开的登录窗口（任务管理器里残留的 msedge/chrome 程序进程
   新版会自动收），再把 `%APPDATA%\xdao-export\browser-profile` 文件夹删掉，重新点
   「用浏览器登录」。
3. 急用不等程序抓：在你登录成功、刷新都不弹回登录页的那扇窗里按 F12 →「应用程序/存储」→
   Cookie，抄出 `userhash=…`，用主界面的「直接粘贴饼干登录」贴进去。

## 下载后核对一下

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.37-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.37-win64.zip.sha256
```

两行的字符串一样就是原件。
