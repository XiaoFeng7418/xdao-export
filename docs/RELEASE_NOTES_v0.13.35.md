# v0.13.35：给每扇窗发一个号 —— 查清「你登的到底是不是程序在看的那扇窗」

## 该下哪个附件

下载 **免安装包** `xdao-export-v0.13.35-win64.zip`（解压后双击 `xdao-export.exe`，不需要装
Python）。同一页还挂着一份 `xdao-export-v0.13.35-win64.zip.sha256` —— 那是给上面这个包核对
用的校验文件，不是程序，不用解压。

## 这一版查什么

v0.13.34 的第四读 + 读罐对账上了真机（m36897）：F12 里 `userhash` 明明就摆着，程序的
**四路读、页内 fetch、HTTP 回放却全都只看到匿名饼干**，两路领饼干页都被弹回登录页。
「读法盲区」这条路基本排除了 —— 剩下的头号解释是**窗口错位**：你登录的那扇窗口，和程序
正在读的那扇，可能根本不是同一扇。最典型的成因：旧版本程序的棕色横幅是「只挂不改」的，
程序换了会话、老窗口的横幅还挂着 —— 你以为横幅在的窗口就是程序的窗口，其实程序早已在
另一扇新窗口里看。

这一版把这三件事变成程序自己说出来的：

- **横幅发号**。每次「用浏览器登录」都生成一个四位十六进制窗口号（如 `3F7A`）。棕色横幅
  末尾带【窗口号 3F7A】，对话框等待文案里报同一个号 —— **号对上的那扇窗才是程序的窗**；
  而且横幅文字每轮刷新，旧窗口留下的冻结横幅会被改成新号，不再冒充。
- **开窗普查**。程序启动浏览器前先扫一遍本机还活着的「自己人」窗口，结果写进运行日志：
  「开窗前普查：探到 N 扇…接手了「××」这一扇」或「没探到…全新开的一扇」—— 有没有复用
  旧窗口、复用了哪一个，日志里一目了然。
- **对账报罐名**。读罐对账那行升级：`挂=…｜罐=<这扇窗饼干目录名>｜全罐=N｜原始userhash=…`。
  「全罐」是不带域过滤的整罐条数，「原始userhash」会把**域名不对或被分区（CHIPS）挡掉**的
  userhash 也点名（只报域名/路径/标志位，绝不报值）。你把「应用」后的对账行发过来，一行
  就能定性：罐不对（读错了窗），还是域/分区被过滤（该补第五读）。

话术同步：横幅与对话框都补了「十几秒没拿到就到『我的饼干』点一行『应用』」的兜底动作，
粘贴提醒与对话框开头都加了「横条末尾带【窗口号】，号对不上的窗口登了也白登」。

## 界面、导出格式、配置文件、命令行开关

布局和 0.13.34 一样；变的是等待话术、横幅文字（多了窗口号），和运行日志里多出来的
「开窗前普查」与升级后的「读罐对账」行。

## 下载后核对一下

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.35-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.35-win64.zip.sha256
```

两行的字符串一样就是原件。
