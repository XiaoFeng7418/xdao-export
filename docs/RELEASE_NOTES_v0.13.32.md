# v0.13.32：你登的是你的浏览器，程序等的是它自己开的窗口 —— 现在它自己说破

## 该下哪个附件

下载 **免安装包** `xdao-export-v0.13.32-win64.zip`（解压后双击 `xdao-export.exe`，不需要装
Python）。同一页还挂着一份 `xdao-export-v0.13.32-win64.zip.sha256` —— 那是给上面这个包核对
用的校验文件，不是程序，不用解压。

## 这一版修了什么

真机复验 v0.13.31 时撞上的最误人的误会：有人在**自己平时用的浏览器**里登录 X 岛、点「应用」
领了饼干，F12 里 `userhash` 明明摆着，程序却干等十几分钟报「还没有 userhash」。

这不是读漏了 —— 是**根本不该看见**。「用浏览器登录」开的是程序自己的一次性窗口（独立资料
目录、不碰你平时的浏览器），跟你自己开着的那个是**两罐互不可见的饼干**。程序只盯着自己那个
窗口，你登得再成功它都看不到。老版本对这个误会的处理只有角落里一句小字，等的人不会去翻。

这一版把它说破：

- **「已经等了 N 秒」那句状态直接写明**：在自己平时用的浏览器里登录，程序看不到 ——
  已经登好了就点「直接粘贴饼干登录」，把 userhash 抄过来。
- **等满两分多钟还没登录，程序主动提醒一次**（只说一次，不刷屏）：常驻那一行会写出
  「多半是你登录的窗口不是程序看的这个」，同时左下角的「直接粘贴饼干登录」按钮换成
  「**抄 userhash 过来登（更快）**」，不用你自己发现。

顺带一句实话，也是设计原则：程序**不会**去读你自己浏览器的数据。实测过（本机）：浏览器开着
时它的饼干库文件是独占锁死的，新版 Chrome 还把饼干换成了防外部读取的新加密 —— 这是浏览器
防窃密的保护，程序尊重它，也绕不过它。所以「把你浏览器里现成的登录直接搬过来」做不到，
能做的就是把 F12 抄一次这条路指到眼前：点 userhash 行 → 复制下面的 Cookie Value 整串 →
粘进「直接粘贴饼干登录」，三十秒完事。

## 下载后核对一下

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.32-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.32-win64.zip.sha256
```

两行的字符串一样就是原件。
