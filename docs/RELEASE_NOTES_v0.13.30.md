# v0.13.30：程序自己领饼干时，终于长得像你了

## 这一版修了什么

上一版（0.13.29）之后，「用浏览器登录」在真机上还剩一处卡：你在程序开出来的浏览器窗口里
登录得好好的（同一会话甚至能在站里回帖），对话框却报「自动取饼干这条路试过了：浏览器里还是
没有 userhash」，接着「领饼干那条路：登录后没能进入用户系统（X 岛把请求弹回了登录页。）」，
一路到超时。前一半是实话 —— 这个一次性窗口里确实没人去过饼干页，罐里本来就没有 userhash；
真正把路堵死的是后半句：程序拿着浏览器那一罐活饼干自己去领，站点却不认这个「人」。

原因查下来是**长相**：程序自己走 HTTP 领饼干时，发请求用的是一路写死的旧 Chrome UA，
浏览器窗口里跑的是另一个真浏览器的另一身 UA。X 岛一看会话来自两个不同的客户端，把程序的
请求弹回了登录页 —— 而你自己在那个浏览器里回帖、发串都是通的。

这一版两处补齐：

- **领饼干多一条更顺的路（优先走它）**：请浏览器页面自己去问站点 —— 在页面里直接 fetch
  饼干列表 → 应用 → 导出，和回帖用的是同一身份、同一身行头，站点没有理由弹回来。这条路
  只在程序自己开的那一次性窗口里、只跟着站点自己的链接问，**不动你的任何标签页**。
- **HTTP 重放学会照抄浏览器长相**：页面内那条路万一没走通（比如窗口正停在半路），退回
  原来的 HTTP 重放时，程序会先在浏览器里问一句它自己的 User-Agent，带着它去发请求。

两条路都没成时，对话框会把**两条路的结论都摆出来**（「页面内 fetch：…；HTTP 重放：…」），
一眼看出卡在哪；成了则对话框照旧关上、饼干进配置。

顺带把诊断行里「走 HTTP 领饼干：」这个标签改成了「领饼干那条路：」—— 现在这一行里装着
两条路的话，旧标签会撒谎。

## 还是登不上怎么办（这两招现在都好用）

1. 在程序开出来的那个浏览器窗口里，手动打开
   `https://www.nmbxd1.com/Member/User/Cookie/index.html`，对任意一块饼干点「应用」——
   userhash 当场进罐，程序下一次张望（30 秒内）就会自己把它捡回来；
2. 或者在你自己常用的浏览器里登录 X 岛，按 F12 → Application → Cookies 找到 `userhash`
   那一行复制值，用「登录 / 设置饼干」里的「直接粘贴饼干登录」贴进去。

## 下载后核对一下

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.30-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.30-win64.zip.sha256
```

两行的字符串一样就是原件。
