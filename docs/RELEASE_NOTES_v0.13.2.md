# v0.13.2：浏览器登录不再把「正常启动的时差」当成失败

## 那个 10061 是怎么回事

用浏览器登录时，程序会先启动一个独立的浏览器窗口，再去读它的调试接口
（就是那个窗口的「遥控器」）。问题出在这两件事之间的**时间差**上：

浏览器是**先把端口号写进文件、再让调试服务开始收连接**的。2026-10-01 在真机上量了
六轮：端口文件出现之后，还要 **328~563 毫秒**第一次连接才成功。这中间去读，系统就会
回一句 **`[WinError 10061] 由于目标计算机积极拒绝，无法连接`** —— 看到的就是
「打开浏览器失败」。

以前这里读一次就定生死，撞上这几百毫秒就报错；而用户再点一次「重新打开浏览器」
往往又好了 —— 因为那一次端口已经真的在听了。

## 现在怎么修的

- **自己等过去**：读调试接口改成在 **8 秒预算**内重试（0.1 秒起、逐步放宽到 0.5 秒一次），
  通了就用，不再把浏览器正常启动的时差当成故障。
- **进程死了就当场说**：每次重试前问一句「浏览器还在吗」。如果它已经退出了，就直接
  报「**<浏览器名> 刚起来就退出了（退出码 N）**，所以读不到它的调试接口」，并提示
  关掉拦截软件重试、或者改用「直接粘贴饼干登录」—— 不再让用户对着转圈等满预算。
- **换一个干净资料目录再试一次**：这条时差以外的连接失败（进程当场死、调试端口被拦），
  也会换成备用资料目录重新启动一次浏览器，而不是直接报错收场。
- 路径写错、接口返回坏数据这类「再等也没用」的错，依旧一次就抛，不会白等。

## 这一版没有改什么

界面、导出格式、配置文件、命令行开关都没动，只改了浏览器登录这一条路的重试与报错。

## 升级以后怎么拿到这一版

**已经装了 v0.13.1 的不用手动下载**：等它自己提示「有新版本」，点一下按钮就行。

## 下载

免安装包：`xdao-export-v0.13.2-win64.zip`（解压后双击 `xdao-export.exe`，不用安装 Python）。

## 还是连不上的话

先关掉安全软件 / 代理工具再点一次「重新打开浏览器」；仍然不行就点
**「直接粘贴饼干登录」**：在浏览器里登录 X 岛后按 F12，把 `usrhash` 那条东西粘进去，
一样能登录，完全不依赖调试接口。
