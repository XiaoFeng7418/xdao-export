# v0.13.52：修好「浏览器登录读到了 userhash 却说不认」的根因

## 这一版改什么

1. **根因：只带了一块 `userhash`。** 上一版发出了「读罐详单」，用它里面那三块饼干各请求一次用户系统的
   「饼干」页，结果很清楚：
   - 只带 `userhash`：落点仍是 `…/Member/User/Index/login.html`（3592 字节，正文是登录页与验证码）；
   - 把浏览器里那两块会话饼干（`PHPSESSID`、`memberUserspapapa`）一起带上：落点就是饼干列表页
     （24935 字节，正文里有「退出」「饼干」）。
   也就是说，站点认的是**整罐会话**，孤立的一块 `userhash` 不够。程序从前只把 `userhash` 装进自己的罐
   （`client.import_cookies` 此前只在领饼干那条兜底路上用过），于是每一次核验都被弹回登录页、被判成
   「这块饼干不认」，退回重等 —— 连续几版「登录读不到 userhash」的真根因就在这里。
   这一版改成：核验之前先把浏览器那一罐整个装进客户端（成功会往运行日志写一行
   「整罐饼干已装进客户端（N 块）」），那两块会话饼干此后一直留在客户端里，后面的导出请求也带着走。
2. **「验饼干」那一步的结论当场写进运行日志**（以前只在对话框里闪一下），并占住对话框常驻那一行 ——
   读到值以后那一行原本空着，看上去像程序没看见这次登录。
3. **关窗或取消之前先落一份「读罐详单」**：这份文件过去只在等满 300 秒（乘上续等轮数）之后才写，
   而真机上往往是等不下去直接关窗，唯一能逐字段比对的证据就跟着窗口没了。现在写成了报路径，
   写不成也明说一句。
4. **包里那份 `使用说明.txt` 也干净了**：v0.13.51 只改了仓库里的说明文字、没有重打包，
   那个 zip 里的说明仍是改前的措辞。

## 这一版的自查

- 全量用例 **1871 passed / 7 skipped**（收集 **1878** 项；比 v0.13.51 多 3 项，盯上面这几条）；
- 真机复现脚本 `_scratch/probe_verify_full_jar.py`（本地脚本，不进仓库）：同一块 `userhash` 分三种带法
  各请求一次那张页面，只比对落点与正文特征，不打印任何饼干值；
- 契约用例（文档事实、版本号一致、使用说明分段、文本卫生、打包清单、公开材料）全绿；
- 逐文件行尾复查：`README.md` / `MAINTENANCE.md` / `HANDOFF.md` 仍是 CRLF 且无裸 LF，
  `packaging/使用说明.txt` 仍是 UTF-8 BOM + 纯 LF；
- 免安装包的 `--version` 输出 `0.13.52`，`--selftest` 与本机基线一致。

## 用着有问题

浏览器登录这条路如果还有问题，日志里现在会多出两类行：`整罐饼干已装进客户端（N 块）`（说明整罐已经带上）
与 `验饼干：…`（说明核验收到的原话）。把这两行、`读罐对账` 整行，以及「读罐详单」那个文件一起贴回来即可。
