# v0.19.2：给自绘控件补交互与绘制用例

这一版**不改任何用户能看到的行为**——只补测试。

## 为什么

`xdao/widgets.py` 里是主界面所有自绘控件：圆角卡片、状态徽章、扁平输入框、
链接按钮、进度条。它们没有走 ttk 主题，全靠 `Canvas` 自己画，所以既不会在
主题没加载时自然退化，也没有任何原生控件兜底。

上一轮覆盖率体检里它的行覆盖率是 **79%**，而且此前没有一条直接用例——只有
界面用例顺带把它们造出来过。这类代码出问题很难发现：圆角半径算错只是「看着
有点怪」，进度条取整错要跑很久才看得出来，输入框焦点框画偏了更是只有少数人
会注意到。

## 这一版做了什么

新增 `tests/test_widgets.py`（56 条用例，需真 Tk，无头环境自动跳过）。覆盖：

- **圆角矩形**：多段线点数与半径随尺寸变化、半径大于半边时被夹住、同样的
  `(宽, 高, 半径)` 命中缓存、引用被清掉后能重新生成；
- **状态徽章**：几档状态各自的配色、文字与圆点直径；
- **扁平输入框**：焦点边框颜色切换、`set` 写回变量、宽度不足时视图会滚动；
- **链接按钮**：配色与手型光标、点击回调、悬停高亮与移开还原；
- **进度条**：`0 / 部分 / 满 / 超界` 四种取整、`configure` 改色、停止不报错。

写用例时踩到两个与 Tk 环境有关的坑，顺手记进了 `MAINTENANCE.md`：

1. 无头或隐藏窗口下部件并没有映射，`event_generate` 送的鼠标事件到不了控件，
   用例会写成「单跑绿、连跑红」。改成截获构造函数注册到事件上的回调直接调用。
2. 给 `_redraw` 这类私有方法打桩之后要显式调一次；靠 `<<Configure>>` 事件
   触发在未映射窗口里同样不可靠。
