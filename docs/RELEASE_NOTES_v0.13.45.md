# v0.13.45：不只看自己接的那一扇窗

## 现象

现场（2026-10-04，v0.13.44）里，日志写：

```
[13:16:00] 开窗前普查：没探到活着的程序窗口，这次是全新开的一扇。
[13:16:09] 读罐对账：挂=https://www.nmbxd1.com/Member/User/Index/login.html｜页=1｜接=端口64231｜
          罐=browser-profile｜按地址读=PHPSESSID｜整罐读=PHPSESSID｜全罐=1｜原始userhash=无｜
          存储读=PHPSESSID｜合并=PHPSESSID
```

而同一张图上，带程序横幅（【窗口号 C597】）的那扇窗，F12「应用程序 → Cookie」里躺着三条饼干，
其中一条正是 70 字节的 `userhash`。程序的三条读法（按地址读、整罐读、存储读）互相一对账全都没问题 ——
说明问题不在读法，在**读的是哪一只罐**。

## 三个探针：把「读法漏了」这条假设排干净

| 探针 | 做法 | 结果 |
| --- | --- | --- |
| `probe_chips_headful.py` | 有头 Edge + 一次性资料目录，`Network.setCookie` 种一块带 `partitionKey` 的饼干再读 | 按地址读看不见；整罐读、存储读、并集**都看得见** |
| `probe_cross_target.py` | 同一个浏览器开两条标签，互相读对方的罐 | 两条标签的名单**完全一致**（`hasCrossSiteAncestor=True` 的分区饼干也看得见） |
| `probe_browser_endpoint.py` | 用 `/json/version` 的 `webSocketDebuggerUrl`（F12 走的那条浏览器端点）读 | 名单与页面会话**完全相同** |

于是「分区饼干读不到」「读法按标签/上下文分」「只有浏览器端点看得见」三条假设全部排除，
只剩一种解释：**程序读的那只罐，与你看着并登录的那扇窗不是同一只**。

## 改法

- `xdao/browser_login.py` 新增 `window_jar()`、`live_window_jars()`、`userhash_across_windows()`：
  自己这只罐里没有 `userhash` 时，把**每一扇还活着的程序窗**（资料目录里记着调试端口的那种）都连上，
  各读一遍整罐（只留域含 `nmbxd` 的），找到就用；
- `jar_forensics()` 多了 `windows_tag` 参数：「读罐对账」那一行末尾多一段 `逐窗=`，
  每扇窗写「端口 + 罐名 + 那一罐的名单」；
- `xdao/gui.py` 的等待循环在每轮 `leaf` 那一刻调入逐窗读，命中的时候对话框会点名是哪一扇窗：
  「在另一扇窗口的罐里找到了 userhash（端口 7002 …）——用它接着往下走。以后请固定在这扇窗里登录，
  程序就省得多问一遍。」；
- 读浏览器饼干出错**不再一声不响**：第一次出错就写一行「读浏览器饼干时出了一次错（…），
  正在下一轮重试；一直这样就把这段日志发出来。」（此前这条路是静默重试，日志会突然停在某一秒。）

功能、界面与导出结果跟 0.13.44 一样，变的是「读罐」这一步会多看几眼、并把看到的说清楚。

## 真机核验

- 全量用例 **1821 passed / 7 skipped**（收集 1828 项）；
- 契约用例（文档事实、版本号一致、使用说明分段、文本卫生、打包清单）全绿；
- 逐文件行尾复查：`README.md` / `MAINTENANCE.md` / `HANDOFF.md` 仍是 CRLF 且无裸 LF，
  `packaging/使用说明.txt` 仍是 UTF-8 BOM + 纯 LF，`xdao/*.py` 仍是纯 LF。

## 登录还是不行的话怎么自救

「读罐对账」那一行末尾现在有 `逐窗=`，几种形状对应几种毛病：

1. `逐窗=` 里别的窗口有 `userhash`、你在看的那扇没有 → 程序会点名；以后固定在那扇窗里登录；
2. `逐窗=` 里每一扇都没有 `userhash`（连你在看的那扇也没有）→ 那一刻登录还没成，把整行贴回来；
3. 行里有 `原始userhash=` 却没有 `合并=` → 是域/路径过滤把它挡住了，把整行贴回来；
4. 日志停在半路、也没有「读浏览器饼干时出了一次错」→ 那是老版本；这一版起出错会自己写一行。
