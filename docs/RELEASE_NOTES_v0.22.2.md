# v0.22.2：修上一版的自动检查配置

功能与 v0.22.1 完全一样，产物也一样。这一版只改仓库里的自动检查配置 ——
上一版把「同时缓存下载依赖」写进了 CI，可这个仓库没有依赖清单文件（只用标准库），
GitHub 跑测试的第一步找不到清单就直接报错，三条自动检查全红。

## 原因

- v0.22.1 给两个 workflow 的 `actions/setup-python` 都加了 `cache: pip`，想省掉每次
  4~12 秒的依赖下载；
- 这个仓库没有 `requirements.txt`，也没有 `pyproject.toml`（运行时只用 Python 标准库），
  setup-python 找不到可缓存的清单，在测试开始前就报
  `No file ... matched to [**/requirements.txt or **/pyproject.toml] for pip`；
- 于是推 `v0.22.1` 之后，打 tag 的构建、主干测试、标签测试三条 run 一开始就红 ——
  不是用例坏了，是准备工作就失败了；
- 依赖本身只有 `pytest` 与 `ruff` 两个，装一次几秒，不值得为一个缓存功能去维护依赖清单。

## 改了什么

- **去掉 `cache: pip`**：`.github/workflows/tests.yml` 与 `.github/workflows/build.yml`
  都删掉那一行，并在原处写明原因，避免以后又有人「同时」加回来；
- 其余步骤一律不动：超时上限、钉住的 `pytest==9.2.0` / `ruff==0.17.5` /
  `pyinstaller==6.22.2`、打包前先跑单元测试、`--version` 冒烟断言，全部保留；
- **代码一行没改**：导出行为、命令行开关、配置项、文件名模板都与 v0.22.1 相同。

## 读数

- 测试：2813 项，本机 2806 通过、7 项真机用例默认跳过（与 v0.22.1 相同）；
- 自动检查：三条 run 恢复全绿（构建 / 主干测试 / 标签测试）。

## 升级建议

已经在用 v0.22.1 的话，不必为这一版重新下载 —— 两边功能完全一样。
只有想留一份「配置最干净、检查全绿」的存档时才需要换。
