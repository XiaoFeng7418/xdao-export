# v0.22.4：打包自检改按 exe 的版本资源判

功能与 v0.22.3 完全一样，产物也一样。这一版只修打包那一步的自检。

上一版把「包里程序的版本号对不对」从「打印出来」改成了「判失败」。可 PyInstaller 用
`--windowed` 打出来的程序没有控制台，GitHub 的 Windows 机器上抓不到它的输出
（日志里那句是 `--version → 退出码 0：`，冒号后面空白），于是这条判断在自动检查里
必然失败 —— 本机抓得到，所以本机一直是绿的。

## 原因

- v0.22.1 起，打包脚本在出 zip 之前会跑一遍 `--version`，输出里没有当前版本号就判失败；
- v0.22.0 的成功构建日志里，同样的位置也是空白 —— 只是那时这行只打印、不判；
- 所以 v0.22.3 的构建 job 在「打包（含文档自检与 BOM 自检）」这一步红了，而包本身是好的。

## 改了什么

- **`tools/build_zip.py`**：新增 `pe_product_version()`，用 ctypes 读 exe 里的 PE 版本资源
  （`ProductVersion`）；`--version` 的输出里认不出当前版本时按它判，两条路都认不出才失败；
- 语言块名按「langid 小端 WORD + 代码页小端 WORD」解码（`04 08 b0 04` ⇒ `080404B0`）——
  第一版直接拼字节十六进制，查不到、读出 None，这一点也写进了用例；
- 判定抽成纯函数 `version_check(version, output, pe_version)`，`main()` 只负责打印与退出码；
- **`tests/test_build_zip.py`** 补 6 条用例：输出里有版本号、输出空的但 PE 版本对得上、
  PE 版本不对、两个都没有、输出有但 PE 读不到、本机打包产物能读到当前版本；
- 其余一律不动：导出行为、命令行开关、配置项、文件名模板都与 v0.22.3 相同。

## 读数

- 测试：2819 项，本机 2812 通过、7 项真机用例默认跳过（比 v0.22.3 多 6 条，全在 `tests/test_build_zip.py`）；
- 自动检查：构建 / 主干测试 / 标签测试三条 run 全绿；构建这一步第一次在 CI 上按 PE 版本判定成功。

## 升级建议

已经在用 v0.22.1 / v0.22.2 / v0.22.3 的话，不必为这一版重新下载 —— 功能完全相同。
只有想留一份「打包自检在 CI 上也成立」的存档时才需要换。
