# v0.13.48：把「到底是哪一扇、哪一只罐」写清楚

## 这一版改什么

还是同一件事：F12「应用程序 → Cookie」里明明有的 `userhash`，程序就是读不到。上一版换了个方向
（去问同一只浏览器里别的「罐」），真机上复验**仍然读不到** —— 那一轮的日志是这样的：

```
读罐对账：挂=…/Member/User/Index/login.html｜页=1（…/Member/User/Index/login.html）｜接=端口61823｜
罐=browser-profile｜按地址读=PHPSESSID｜整罐读=PHPSESSID｜全罐=1｜原始userhash=无｜存储读=PHPSESSID｜
页面JS=PHPSESSID｜合并=PHPSESSID｜逐窗=没有别的活窗口｜哑窗=browser-profile
```

而同一个端口、挂着程序横条的那扇窗（顶上还有冻结版才补的 `--no-sandbox` 警告条，说明确实是程序
起的），标签是「首页 - User System - X岛提示板」、地址是 `…/Member/User/Index/index.html`（**已经
登录了**），F12 里 Cookie 有三条，其中 `userh…` 就是 70 字节的那一块。

**矛盾点：同一个端口上，程序读的页面是 `login.html`（罐里只有 `PHPSESSID`），用户眼前那扇是已登录
的 `index.html`，而日志写着「页=1」。** 这一版不去猜，先把「怎么把这件事写清楚」做掉：

1. **对账行多一段 `窗口=`。** 浏览器里每个标签页、它挂在哪一份罐、地址是什么，一行写清，形如
   `窗口=第1扇（默认）https://…；第2扇（上下文3f2a1b）https://…`。上一版的「页=」只数得出「有几个
   标签」，数不出它们各在哪份罐里 —— 于是「程序读的那扇」和「你看的那扇」是不是同一扇，过去在日志里
   根本对不出来。
2. **对账行多一段 `罐路径=`。** 「罐=」只有目录名，而配置目录下的常驻罐与临时目录里的一次性罐**可能
   同名**；现在写的是这次真正在用的那只资料目录的**完整路径**。
3. **`同罐进程=` 数出 0 也照写。** 过去只在多于 1 时才写这一段，于是「这一段缺席」和「查了、就一只」
   在贴出来的日志里长得一模一样 —— 而这两件事的诊断意义正相反。
4. **修掉一个真漏洞：用户自己开的无痕窗不在浏览器自报的上下文名单里。** 本机探针实测：`msedge.exe
   --incognito` 起浏览器时 `Target.getBrowserContexts` 回的是 `[]`，而那个页面目标身上明明挂着
   `browserContextId=…` —— v0.13.47 的 `别路=` 就是在这里读空的。现在上下文名单改成把「浏览器自报的
   名单」与「每个目标各自报的上下文」**两处并起来**，无痕窗里登录挣来的饼干也在名单里了。
5. 等超时那一刻落盘的「读罐详单」里，同样多抄了 `罐路径` 与每个目标各自的上下文。

功能、界面与导出结果跟 0.13.47 一样，变的是「读不到」时留下的证据。**登录方式交互没有变**：程序
依旧不替你点『应用』。

## 登录还是不行的话怎么自救

「读罐对账」那一行现在有六段证据（`逐窗=` / `哑窗=` / `同罐进程=` / `别路=` / `窗口=` / `罐路径=`）：

1. `窗口=` 里能看到你眼前那扇标签、而程序接的是另一扇（地址不一样）→ 请在那扇窗里完成登录（窗底挂着
   横条的那一扇才是程序盯着的；横条上有窗口号与端口）；
2. `别路=` 或 `逐窗=` 里那一份有 `userhash` → 程序会自己拿来用，并点名是哪一份；
3. `逐窗=没有别的活窗口`、`哑窗=` 里点了一扇 → 那扇窗的调试端口已经哑了，把它关掉重开一次；
4. `同罐进程=` 大于 1 → 还有第二个实例在用同一只资料目录，把它们关掉，只留程序起的这一只；
5. 六段都没问题、这一罐里就是没有 `userhash` → 那一刻登录还没成：把整行贴回来，顺手把日志里那份
   「读罐详单」也发出来（记得先自己看一眼值）。

懒得折腾就走对话框里的「直接粘贴饼干登录」：在你平时用的浏览器里登录 X 岛，按 F12 →
应用程序 → Cookie → `https://www.nmbxd1.com`，把 `userhash` 的值抄进去。
