# v0.21.9：给一键升级的下载、自检、替换补用例

这一版不改任何用户能看到的行为——只补测试，把「一键升级」这条会动用户文件的链路钉进用例里。

## 为什么

一键升级做四件事：下载新版、给它跑一遍自检、问一句、交给帮手进程替换目录。它写错了不会报错，只会让用户看到「升级完成」而目录其实没换——v0.16.x 就踩过：`root.quit()` 之后进程还在，帮手等满 60 秒放弃，用户以为升级成功。

这条链路此前几乎没有直接用例：`_upgrade_worker` 一行没测，`_start_upgrade` / `_poll_upgrade` / `_finish` 只有零星覆盖。

## 这版做了什么

`tests/test_window.py` 92 → 110：

- 主线程这一侧八条——开始升级标记忙碌并排一次轮询；已在升级时忽略第二次点击（否则会同时换两遍文件）；下载进度在「知道总长度」时显示百分比、不知道时显示已下多少 KB；自检通过后问一句并把答案回传给工作线程（答否要留日志）；失败收尾弹原因、按钮回到「有新版本」；成功收尾写「升级完成」并让位（不能弹模态框，否则帮手等不到进程退出）。
- 工作线程这一侧六条——不能原地升级时直接收手；发布里没有免安装包时说人话；自检没过绝不替换；用户在最后一刻反悔时丢掉暂存；一路通过时交给帮手且**不删**暂存（帮手正要用里面的新版）；工作线程里抛异常只交一条 finish 回来，绝不把界面带走。

`tests/test_gui_entry.py` 136 → 139：监控窗口「编辑选中」的三条（没选中要提示、选中后按 id 找对目标、树里留着已失效的 iid 时安静返回）。

`tests/test_window.py` 另加四条 `_jar_holds_a_session` 的判定（只有匿名会话号不算登录、出现会员饼干才算、名字不分大小写、空值与杂项不崩）。

## 顺手修的一条抖动

`tests/test_gui_browser_login.py` 里有一条用秒表断言「续等不超过 X 秒」的用例，带覆盖率或跑全量时会被拉长而偶发失败。这版把上限放宽成「只要没多续一整轮就算过」，下界（真的续等了两轮）保留。
