# v0.13.22：自动应用饼干那一步搬回程序自己（0.13.21 的现场复验仍卡）

## 现象

0.13.21 里登录是好的，程序也会自己跳到「饼干」页，可是**自动应用饼干之后仍然一直卡住**。
用户复验的截图：浏览器停在 `https://www.nmbxd1.com/Member/User/Cookie/switchTo/id/461037.html`，
页面是站点自己的「饼干切换成功!」+「页面自动 跳转 等待时间： 0」，界面上一直说「这个窗口里
还没登录（页面停在登录页）：先在里面登录 X 岛。」，日志只有「就绪」与「已是最新版本
（0.13.21）。」两行。

## 原因

那张跳转页的跳转是**页面自己的 JS 倒计时**干的（`<a id="href" href="…">` + `setInterval`
到点 `location.href = href`）；成功页的 `a#href` 指回自己时就变成原地重载 —— 用户看到的
「一直跳转」就是它。更要紧的是：**站点给 userhash 的落点不是那一跳的落地页，而是「导出页」
的响应体**（一段 `{"cookie": "…"}`）。让浏览器自己去跳，等于把「能不能拿到 userhash」
押在渲染无关的东西上。

## 改法

- 浏览器窗口只负责让用户把验证码认过去：登录成功后程序**读一次它的整罐饼干**，剩下的交给
  从 v0.6.1 起就在线上跑通的 HTTP 流程（认「跳转提示」页、跟着跳、从导出页正文里抠出
  userhash），**一个页面都不动**。
- 浏览器那条路照旧先跑，领不到时才走 HTTP 兜底；「用户可能还在打验证码」只在**这一轮没动过
  页面、也从来没真应用过**、且罐里只有一个匿名会话号时成立 —— 否则「标签页被弹回登录页、
  罐里其实还登录着」那种场面会永远卡住。
- 导入整罐饼干时，同名的旧饼干按名字扫干净（不分域、不分路径），避免一个请求里出现两条
  `userhash`（`set_userhash` 的注释里记着这个实测过的坑）。

界面布局、导出结果与 0.13.21 完全一致。

## 真机核验

- 本机全量：1640 passed / 7 skipped（共 1647 项）。
- 反向验证：九处注入（罐子判据两头改错、整段停用 HTTP 兜底、领回来的值不校验、那条原话不
  挪到「试过的几步」末尾、服务端那句话不原样带出、导入前不扫同名旧饼干、会话饼干当成过期、
  空条目照装）全部变红；三个源码文件按字节还原后一致（`xdao/gui.py` sha256 前 16 位
  `94315cad44bbc1c4`、`xdao/browser_login.py` `46948fb7ace58d29`、`xdao/client.py`
  `b9f7505a885d5b83`）。
- 打包版：`--version` 报 `X岛串导出工具 0.13.22`；`--selftest` 与上一版逐行差异只有版本号与路径；
  包内 `使用说明.txt` 与仓库里的那份逐字节一致；`tools/repo_check.py` 14 项全过。
