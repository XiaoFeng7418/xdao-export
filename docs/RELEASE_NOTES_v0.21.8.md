# v0.21.8：给「挑选饼干」窗口与从串里读饼干补用例

这一版不改任何用户能看到的行为——只补测试，把「从串中挑选…」这条链路钉进用例里。

## 为什么

「从串中挑选…」会读第一个串的第一页，把这一页里出现过的饼干按发言数列出来，让用户勾选后写回筛选框。它决定导出的范围对不对，而它的核心 `CookiePicker.__init__` 是整份 `xdao/gui.py` 里剩下最大的一块未覆盖代码（41 行）。

它坏掉时的表现很安静：勾了、点了「应用」、筛选框却没变；或者「← PO」标到了别人身上。

## 这版做了什么

- `tests/test_window.py` 82 → 92：
  - 窗口层五条——已经在筛选框里的饼干预先勾上；按发言数降序列出、PO 标记唯一；应用后写回筛选框并关窗；一个都没勾时清空；「全选 / 全不选」。
  - 入口层七条——没有网址、第一个网址认不出串号各一条提示；读到第一页后按 `user_hash` 计数并带 PO 饼干开窗；读失败弹「读取失败」；第一页没有饼干时给提示；队列还空着时按 80 毫秒继续等。
- 顺带记下两个写法坑：`CookiePicker` 构造时 `grab_set()` 在未映射窗口上会抛 `TclError`，用例要临时按掉；`_poll_cookies` 的按钮复位写在取到消息之后，直接手调时别断言按钮状态。
