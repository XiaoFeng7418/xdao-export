# v0.19.1：给 CDP 传输层补齐协议层用例

这一版**不改任何用户能看到的行为**——只补测试，并且顺手把上一版漏写的一句说明补上。

## 为什么

`xdao/cdp.py` 是手写的 DevTools WebSocket 客户端：和浏览器调试端口握手、收发帧、
按 id 把命令应答配给调用方。登录流程读饼干、PDF 渲染打印页面，两条关键链路都压在它身上。

上一轮覆盖率体检里，它的行覆盖率是 **73.9%**，是整个项目最低的一块，而且此前没有任何
直接用例——只有 `test_browser_login.py` 顺带用到它的一部分。这类代码出问题的表现特别
隐蔽：握手少读一个余包，症状是「命令永远等不到应答」；帧长度解析错，症状是「大一点的消息
就断线」。等用户报上来，很难从现象倒推。

## 这一版做了什么

新增 `tests/test_cdp.py`（111 条用例）。不碰真浏览器：用 `socketpair` 造一对连接，另一端
写了个假 CDP 服务端——它会自己算握手应答、按命令回话、也能发事件通知 / 分片 / ping / close。

覆盖到：

- **帧层**：掩码、`0/126/127` 三种长度分支、分片 opcode、握手余包优先、对端关闭；
- **握手层**：RFC 6455 的 Accept 校验向量、路径与查询串、非 101 应答、Accept 不对、被关闭；
- **调试接口**：JSON 解析失败、`_retryable_read_failure` 认 errno / winerror / 超时 / 异常链、
  重试到成功、预算用完放弃、`hint` 提前报错、不该重试的错误不重试；
- **选页面标签**：`pick_page` / `pick_site_page` / `_context_ids_of*` / `_describe_exception`；
- **会话**：命令与应答按 id 配对（乱序也认）、事件与非整数 id 忽略、分片拼回整条、
  ping 自动回 pong、超时报错、`close()` 叫醒还在等的调用、`retarget` 的四种去向、
  三条读饼干的路（其中一条失败就用另一条）、`evaluate` 的字符串 / 对象 / 异常 / 空值。

顺带在用例里记下两个 Windows 细节，免得以后重踩：

1. `socketpair` 关掉一端，另一端拿到的是 `WinError 10054`（对端强制关闭），不是干净的 EOF——
   所以「被对方关闭」这条分支用假 socket（`recv` 返回 `b""`）复现，而不是真关 socket。
2. 给 `read_frame` 打桩要打在**类**上。打在实例上时，读线程早就阻塞在 `recv` 里了，桩不会生效。
