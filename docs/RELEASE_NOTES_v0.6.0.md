# v0.6.0：缺页会自己补抓，界面能换深色

这一版做了路线图上的两件事：**单页失败自动补抓与重试队列**、**暗色模式切换入口**，
另外修掉了两个会让用户白跑一趟的毛病。

## 出了什么问题

### 一、一页失败，后面的页就都不抓了

抓长串的时候只要有一页没抓下来（网络抖动、接口超时、临时被限流），
旧版会**直接从这一页停住**，后面的页一页都不再试：产物少了一大截，
界面和日志却一句都不提，用户拿到手才发现内容不全。

这类"静默缺页"藏得深：某页失败后，下一次导出还会因为缓存元数据写成了
"已经抓到第 N 页"而直接复用缺页的缓存 —— 缺的那页永远补不上。

### 二、导出结束时界面崩一下

```
NameError: name 'output_dir' is not defined
```

导出线程结束回到界面收尾时，读的是一个只存在于另一个方法里的局部变量，
于是**抓取结果都好好的，收尾那一下弹"界面出错"**。

### 三、登录了还是被接口拒绝

有人反馈：登录成功、饼干也应用了，导出时仍然报
`必须登入领取饼干后才可以访问`。查下来是服务端不认这份 userhash
（饼干失效/账号掉线），但界面只把这句话原样贴出来，看不出该做什么。

## 这一版改了什么

- **单页失败自动补抓**：某一页失败不再中断整趟导出，失败页先记下来、
  后面的页继续抓；第一遍跑完再对失败页统一补抓，默认补 2 轮。
  补抓之间会等一小会儿（同时失败多页时要退避，不然会被接口限流）。
- **补抓结果会如实汇报**：
  - 补上了 → 日志里写"有 N 页第一次没抓下来，补抓成功。"；
  - 补不上 → 明确写出**缺了第几页**、补了几次、为什么，并提示"再导一次通常就能补齐"；
  - 只在缺页后面的内容也没试过时（多半是断网/限流），会把"连试都没试"的页一起算进缺失，
    不让用户以为只差一两页；
  - 界面上另外弹一次「有串没抓全」，日志逐条列出是哪些串。
- **缺页不再被缓存掩盖**（真 bug）：缓存里记录"抓到第几页"以前写的是
  `max(页号)`，中间缺页时仍会声称完整，下次导出直接复用缺页缓存。现在记的是
  **从第 1 页起连续抓到第几页**，并且要跟接口报的总页数比一次，缺页必定重新去抓。
- **页数上限写进产物说明**：撞到 `max_pages` 时明确说"这次只抓到第 N 页（串比这长）"，
  并提示可以用「指定页码」分批导出。
- **修掉收尾崩溃**（真 bug）：导出结束时改从实例状态里取输出目录，
  不再依赖另一个方法的局部变量。
- **暗色模式**：右上角多了「配色」下拉框，浅色/深色随时切换，选完立刻生效并记住，
  下次启动还是这个配色。日志内容、已经填好的串地址在切换时都不会丢；
  正在导出或监控时不允许切（切了会重建界面，避免打断进行中的任务）。
- **被接口拒绝时给出能动手的提示**：除了原文，还会说明这是服务端不认这份饼干，
  并指向「登录 / 设置饼干」重新登录、或手动粘贴 userhash。
- **重复设置饼干不再叠加同名 cookie**：旧版同一个 cookie 罐里可能留下两条
  `userhash`，请求头会变成 `userhash=新; userhash=旧`，服务端取哪一条并不确定。
  现在设置前会先清掉旧值。

## 你现在该怎么做

1. 下载下面的免安装包，解压，双击 `xdao-export.exe`。
2. 导出长串时留意日志：出现"注意：……"就说明有页没抓全，照着提示再导一次即可
   （已经抓下来的页都在缓存里，重跑只会补缺的页）。
3. 想让眼睛舒服点：右上角「配色」→ 深色。
4. 如果仍然看到"必须登入领取饼干后才可以访问"：点「登录 / 设置饼干」重新登录一次；
   还不行就把浏览器里的 userhash 值手动粘贴进去（说明见日志里的提示）。

## 下载

- `xdao-export-v0.6.0-win64.zip`（推荐，也是唯一的附件）：**免安装包**，解压后双击
  `xdao-export.exe`；包内附 `诊断写入.ps1` 与 `诊断写入-双击运行.cmd`。
  不做任何解压动作，中文路径与受限环境都能启动。
- 单文件版自 v0.5.1 起不再提供：PyInstaller 的单文件版在含中文的路径下会直接
  报 `Could not create temporary directory!`，属于打包器的限制，不是程序本身的问题。

## 测试

`338 collected / 337 passed, 1 skipped`（跳过的那项需要真实网络环境）。
这一版新增 24 项回归用例，覆盖：

- 重试队列：抖动页补抓成功、补抓全失败时如实报缺页、关掉重试、多页同时失败时
  把"没试过"的页一起算进缺失、缺页的下一次导出只补缺的那几页、首页致命错误仍然要抛；
- 缓存不再谎报完整：串比缓存长时会去抓尾巴、撞页数上限时标记产物不完整；
- 界面：输出目录不再依赖局部变量、缺页汇总、切换配色会重绘且保留用户输入、
  同配色不重复重建、导出中拒绝切换、打开的对话框跟着换色；
- 主题：`PALETTE_FIELDS` 覆盖每个字段、配色映射可往返、下拉候选表用当前配色；
- 设置：主题能存能读、不认识的主题回落到浅色；
- 客户端：重复设置饼干不留同名旧 cookie。
