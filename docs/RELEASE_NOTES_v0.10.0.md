# v0.10.0：打包版也能导出 PDF 了

免安装包（Releases 里的那个 zip）从 v0.3.0 起一直有个说不出口的限制：**导不出 PDF**。
选 PDF 会自己降级成 HTML，然后提示你「在浏览器里打开它按 Ctrl+P 另存为 PDF」。
需要真正的 PDF 只能去装 Python、从源码跑 —— 对一个"解压双击就能用"的工具来说，这很别扭。

这一版把它修掉了：**打包版现在能直接导出 PDF**，纸张、页边距、缩放、页码范围这些设置也一并可用。

## 根因：浏览器自己的沙箱

打包版执行 `-f pdf` 时，Chrome / Edge 的子进程会以
`2147483651`（`0x80000003`，STATUS_BREAKPOINT）退出，一份 PDF 都产不出来；
同样的参数从命令行手工启动浏览器却完全正常。

当年（v0.3.0）排查过 Tcl/Tk 环境变量、继承的环境、工作目录、管道捕获输出、
进程树继承、句柄继承、作业对象（job object）等等，全部不是；
最后归因成"PyInstaller 冻结进程启动浏览器属于系统级限制，绕不过去"，于是加了自动降级。

这次重新验证，逐个排除之后找到了真正管用的那一个开关：**`--no-sandbox`**。

也就是说：**崩掉的是 Chromium 自己的沙箱层 —— 当它的父进程是一个 PyInstaller 冻结程序时，
沙箱初始化会失败。** 跟有没有显示器（headed / headless 都崩）、跟句柄继承、跟环境变量、
跟启动方式都无关。以前之所以误判成"系统级限制"，是因为只试了自家代码这边的嫌疑，
没试浏览器自己的开关；而手工从命令行启动又恰好因为父进程不是冻结程序而一切正常。

## 这一版怎么做

- **只在打包版**给浏览器加这一个开关：判断依据是程序自己是否被冻结
  （打包运行时 `sys.frozen` 为真才加）。
- **源码运行不加**：`python main.py <串号> -f pdf` 仍然带沙箱，行为和以前一样。
  这样既修好了打包版，也没有在能带沙箱的场景里把沙箱关掉。
- 渲染的内容仍然是**本程序自己写出来的本地 HTML**（数据来自你抓取的那个串），
  不会去打开远程页面。
- **HTML 降级照旧保留**：浏览器真的起不来时（机器上没装、路径填错、被安全软件拦下），
  程序仍然会把内容存成 HTML 并告诉你怎么办，不会卡在那里。这一版的提示文案也顺势改准确了 ——
  以前一律说"打包版无法启动浏览器，请从源码运行"，现在会指向真正可能的原因。
- **`--pdfdiag` 诊断跟着一起修**：它会打印当前是不是打包运行、会加哪些浏览器参数，
  并用与正式导出**完全相同**的参数启动一次浏览器。以前的诊断走的不是同一条路，
  容易给出误导性的"启动失败"。
- **顺手补了一处缓存目录的兜底**：挑缓存位置时会问一次系统临时目录；个别环境里这一问
  会直接抛异常（`No usable temporary directory found in [...]`）。缓存只是加速手段，
  问不到就少一个候选位置，不该把整次导出带走 —— 现在它会跳过这一处继续，
  并且有用例钉住这个行为。

## 你现在该怎么做

1. 下载下面的免安装包，解压，双击 `xdao-export.exe`（覆盖旧版即可，配置与缓存都不用动）。
2. 导出一个串、格式选 PDF，确认文件正常打开。
3. 如果仍然失败，请运行一次 `xdao-export.exe --pdfdiag`（在解压目录里开命令行），
   把输出发给维护者 —— 它会说明浏览器是不是真的起不来。

## 下载

- `xdao-export-v0.10.0-win64.zip`（推荐，也是唯一的附件）：**免安装包**，解压后双击
  `xdao-export.exe`；包内附 `诊断写入.ps1` 与 `诊断写入-双击运行.cmd`。
- 单文件版自 v0.5.1 起不再提供：PyInstaller 的单文件版在含中文的路径下会直接报
  `Could not create temporary directory!`，属于打包器的限制，不是程序本身的问题。

## 已知边界（如实说明）

- **PDF 仍然需要本机装有 Chrome 或 Edge**（Windows 上基本都有）。没有浏览器、
  浏览器路径填错、或者被安全软件拦下时，程序会改存 HTML 并说明原因。
- **源码版与打包版的浏览参数现在略有不同**（只有打包版带 `--no-sandbox`），
  这是为了兼容打包运行时的限制；两条路径的渲染结果一致。
- **网页自己声明了 `@page { margin: … }` 时，边距以页面为准**：这是浏览器的行为，
  绕不过去，所以「跟随网页样式」才是推荐默认值。
- **登录仍需要真人处理一次验证码**：视觉识别对 X 岛验证码的准确率太低（实测 3 张只认对
  一张半），所以不做自动登录，这一点没有变。

## 测试

`962 collected / 956 passed, 6 skipped`（6 条 skipped 都要显式开关才跑：`XDAO_BROWSER_TEST=1`
拉起真实浏览器、`XDAO_LIVE_NOTIFY=1` 真弹一次系统通知、`XDAO_PDF_TEST=1` 用真浏览器渲染
PDF 并核对纸张尺寸）。本版新增的离线用例覆盖：

- **开关本身**：常量就是 `--no-sandbox`、只在冻结时生效、返回的是新列表
  （改它不会污染模块里的常量）、不传参数时按当前进程判断；
- **两条启动路径都真的带上了**：PDF 的命令行渲染路径与浏览器登录的启动参数各有一条用例，
  删掉传递就会红（做过变异校验）；
- **源码运行不带这个开关**：同样有用例钉住，免得哪天顺手把沙箱关掉。

**真机核验**（不是靠改 `sys.frozen` 的单元用例）：用 PyInstaller 单独打了一个
`console=True` 的冻结小程序，在**真实的冻结环境**里同一次运行对照 ——
不加开关：`Chrome 没有生成 PDF（退出码 2147483651）`；加上开关：
**成功，65,290 字节、`%PDF` 魔数正确、1 页、612.0x792.0pt**。
另外，打包版本体也重新跑了一遍 `--pdfdiag`（源码运行四种启动方式全部
`退出码=0 生成PDF=是`），并用打包好的 `xdao-export.exe` 真机导出了一个真实串：
**退出码 0，产出 256,836 字节的 PDF，页数 1，`/MediaBox 0 0 612 792`，缓存目录也真的写进去了**。
