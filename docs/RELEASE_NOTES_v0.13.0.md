# v0.13.0：点一下就能升级

上一版（v0.12.0）会在有新版本时告诉你一句；这一版更进一步 —— **点一下，它自己下载、自己换、自己重启**。

## 它怎么工作

从「有新版本」到你用上新版本，一共五步，每一步都会写进运行日志：

1. **问你一句**：点带「有新版本」的按钮，它会告诉你新版本号和下载包大小，问要不要现在下载并安装。
2. **下载**到系统临时目录（`%TEMP%\xdao-export-update`），带进度百分比，下载期间界面照常能用。
3. **解压**，并且只认升级包里那个 `xdao-export-v*-win64` 目录，压缩包里的越界路径会被挡掉。
4. **先给新版本做自检**：跑一遍新版本的 `--selftest --offline`（版本、Python、系统、配置目录、
   导出目录、缓存目录、浏览器、导出格式八项）。**自检不过就什么都不换**，现场保持原样。
5. **自检通过再问你一次**（「现在就用它替换当前程序吗？」）；你答是之后才动文件：先把旧目录
   改名留作备份，再把新版本搬进来，然后自动启动新版并退掉自己。

## 出问题能回退

- 旧版本**不会被删掉**，只是改名成 `xdao-export-v0.12.0-win64.old-<时间戳>` 留在原地。
  新版真起了不来，把名字改回去就行。
- 备份**保留 24 小时**，之后每次启动时顺手清掉，不会越积越多。
- 换文件之前任何一步失败（没网、下不动、解压坏了、自检没过、你中途取消），
  都只是「这次不换」，暂存目录一并清掉，**现场一个字节都不动**。

## 什么时候不能原地升级

程序会自己判断，不能升就**如实说明原因**，然后照旧给你下载页，绝不硬来：

- 从源码跑（`python main.py`）—— 没有可换的目录；
- 程序目录或它的上级目录写不进去（比如装在 `C:\Program Files` 又没提权）；
- 这个版本的发布里没挂免安装包。

## 命令行

```powershell
python main.py --check-update        # 查有没有新版
python main.py --check-update-json   # 输出 JSON（多带了升级包的名字与大小）
```

`--apply-update` 是升级过程内部用的开关（帮手进程靠它做事），不建议手工调用。

## 首发之后补掉的三件事（同一个 v0.13.0 里已修好）

第一版免安装包放出去之后，真机跑下来发现三个问题，都在现在这个包里修掉了：

- **升级点完显示「已就位」，实际没换**：老程序退出的那一步不行 —— `root.quit()` 只是
  从界面主循环里退出来，进程本身还站着，帮手等满 60 秒只好放弃，界面却已经报了成功。
  现在退出走的是「关窗口 + 立刻结束进程」，帮手等得到。
- **升完级 `%TEMP%` 里剩一个几十 MB 的暂存目录**：顺手搬文件的帮手跑的就是升级包里的
  exe，自己正住在暂存目录里，Windows 不许删正在运行的自己。现在换完目录就把它改个名
  留个记号（`xdao-export-update.leftover-…`），新版启动后盯一会儿、等帮手真的走了就收掉。
- **配置目录里的浏览器资料用不了时，浏览器登录会一直失败**：真机上出现过
  「打开浏览器失败：[WinError 5] 拒绝访问」。现在碰上这类「权限 / 被占用」的目录问题，
  会自动换一个临时资料目录再开一次浏览器，并在运行日志里说清楚用的是哪个目录。

## 下载

免安装包：`xdao-export-v0.13.0-win64.zip`（解压后双击 `xdao-export.exe`，不用安装 Python）。

## 已知边界（如实说明）

- 只支持免安装包（zip）原地升级；升级过程依赖程序所在目录可写。
- 升级期间请别自己再开一个程序实例 —— 帮手在等当前进程退出，等不到就不换（会如实报错）。
- 新版本的自检只看本机环境，不联网；联网那两项留给你自己 `--selftest` 复核。

## 这一版没有改什么

导出、监控、PDF、自检都没动。**不升级也完全没影响。**
