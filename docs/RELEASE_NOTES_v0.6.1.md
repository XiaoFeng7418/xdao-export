# v0.6.1：邮箱登录失败时，终于会告诉你为什么

这一版只修一件事，但是件挺气人的事：**用邮箱登录失败时，程序一律说
「未找到可用的饼干」**，让人以为是账号里没饼干，实际上是登录这一步就没成。

## 出了什么问题

有人反馈：邮箱登录点了「登录」之后弹出

> 登录失败
> 未找到可用的饼干，请先在浏览器里登录用户系统并应用一块饼干。

而他改用「饼干直接登录」时一切正常、抓取也没问题 —— 也就是说账号里
明明有饼干，这句提示把人指向了完全错误的方向。

## 根因

X 岛登录失败时用的不是 HTTP 302，而是 ThinkPHP 的**「跳转提示」页**：

- HTTP 状态码是 **200**（看起来像一次正常响应）；
- 页面正文写着服务端的原话，例如 `并没有权限访问_(:з」∠)_，请等待自动跳转`；
- 真正的跳转靠页面里一段 JavaScript 定时器完成 —— **浏览器会自己跳，程序用的
  HTTP 库不会**。

旧版拿这张跳转页当成了"饼干列表页"去解析，一个饼干 id 都找不到，于是抛出
「未找到可用的饼干」。真正的失败原因（登录没生效 / 没有权限 / 账号里确实
没有饼干）被这句误导性文案整个盖掉了。

## 这一版改了什么

- **认识「跳转提示」页**：新增跳转页识别，取出去向和服务端写给用户的那句话；
  请求时遇到跳转页会跟着走（最多两跳），不再把跳转页当内容页解析。
- **登录没有通过时直接说清**：
  > 登录没有通过，X 岛返回：并没有权限访问_(:з」∠)_，请等待自动跳转（已回到登录页）。
  > 常见原因是账号或密码不对，也可能是验证码过期 —— 请刷新验证码后重试。
- **登录成功但进不去用户系统时区分三种情况**，不再一律说"没有饼干"：
  - 被弹回登录页 → 「登录没有生效」，提示重新登录、或改用饼干直接登录；
  - 有服务端原话 → 「没能读取饼干列表」，附上原话；
  - 都没问题、列表真的是空的 → 才说「这个账号还没有饼干」，并给出领取步骤。
- **登录对话框的报错带上标题**：验证码错、密码错、账号有问题、登录没生效、
  这个账号还没有饼干，每种都有自己的标题和一句"接下来做什么"。
- **应用饼干（switchTo）那一跳也跟着跳转走**：这一步被弹回去时不再当成成功。

## 你现在该怎么做

1. 下载下面的免安装包，解压，双击 `xdao-export.exe`。
2. 邮箱登录失败时，照着弹窗里的标题看是哪一类问题：验证码就重填（图片已经
   换成新的一张）、密码不对就确认密码、说"登录没有生效"就再登一次。
3. 实在登不上，用「改用饼干直接登录」：在浏览器里登录 X 岛用户系统，复制
   userhash 粘贴进来即可 —— 这条路一直是可以用的。

## 下载

- `xdao-export-v0.6.1-win64.zip`（推荐，也是唯一的附件）：**免安装包**，解压后双击
  `xdao-export.exe`；包内附 `诊断写入.ps1` 与 `诊断写入-双击运行.cmd`。

## 测试

`348 collected / 347 passed, 1 skipped`（跳过的那项需要真实网络环境）。
这一版新增 10 项回归用例：

- 跳转页识别：能读出 `<a id="href" href="…">` 的去向（两种属性顺序都认）、
  能读出 `class="error"` / `class="success"` 那段文字、普通页面不会被误判；
- 跟着跳转走：请求落点会跟到目标页，相对地址会补成完整地址；
- 登录：跳回登录页时报"登录没有通过"；
- 应用饼干：会话没建立时报"登录没有生效"、会话正常但列表为空时报"这个账号
  还没有饼干"、正常时能取回 userhash；
- 界面文案：五种失败各有标题与下一步、未知错误原样透出。

其中 3 项直接拿线上真实的跳转页 HTML 当样例，不是手写的假数据 —— 这个 bug
正是因为"假数据里没有跳转页"才漏过去的。
