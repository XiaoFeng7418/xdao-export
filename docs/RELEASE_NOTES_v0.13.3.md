# v0.13.3：认系统默认浏览器，并且「起来就退」不再一次定生死

## 这一版修的是「用浏览器登录」这条路

v0.13.2 发出去以后，又收到一条新的报错：

    Edge 刚起来就退出了（退出码 21），所以读不到它的调试接口。

这条消息说明程序已经能说清死因了（v0.13.2 的改动），但**事情还是办不成**：
浏览器进程刚起来就退出，登录窗口根本留不住。真机上拿本机的 Edge / Chrome 反复试
（全新资料目录、现场资料目录、预放过期端口文件、只读目录），**始终复现不出退出码 21**，
所以这一版不去猜那一个原因，而是把「起来就退」当成一类**会被自己绕过去的故障**：

- **换一个干净资料目录再试**：原来的顺序是「先试上次那个目录，不行再换一个」。
  现在只要浏览器是「刚起来就退」，就把所有备用资料目录都试一遍 —— 浏览器资料目录里
  的旧状态坏掉是这类退出码最常见的原因。
- **换一个浏览器再试**：一个浏览器全试完还是这样，就换下一个（Edge → Chrome →
  Chromium → Brave，按系统里实际装了的来）。
- **全都起不来才报错**，而且说清还能怎么办：关掉安全软件的浏览器防护再点一次，
  或者改用「直接粘贴饼干登录」。
- 换过浏览器时界面会写一行说明，不至于让人以为程序挑错了：「**Edge 起不来，这次改用 Chrome。**」

## 认「系统默认浏览器」

之前是按固定顺序挑（Edge 优先），所以把系统默认浏览器改成 Chrome 之后，
程序还是去开 Edge。现在**先看系统默认浏览器**（注册表里 `https` 关联的
`UserChoice`，HKCU 找不到命令行时再去 HKLM 找），认得出就用它，认不出就按
Edge → Chrome → Chromium → Brave 的老顺序兜底。想固定用某一个，仍然可以在设置里
手动指定浏览器路径，手动指定永远优先。

## 顺带清掉的历史包袱

`browser_login.py` 里有三个函数被**定义了两次**（后一个覆盖前一个，前一个从来没被执行过），
这次删掉了重复的那份。删完核对过：它们引用的常量和取值方式，生效的那份全都自带。

## 这一版没有改什么

界面布局、导出格式、配置文件、命令行开关都没动，只改了「用浏览器登录」这条路。

## 升级以后怎么拿到这一版

**已经装了 v0.13.2 的不用手动下载**：等它自己提示「有新版本」，点一下按钮就行。

## 下载

免安装包：`xdao-export-v0.13.3-win64.zip`（解压后双击 `xdao-export.exe`，不用安装 Python）。

## 还是连不上的话

先关掉安全软件的浏览器防护、再点一次「重新打开浏览器」；仍然不行就点
**「直接粘贴饼干登录」**：在浏览器里登录 X 岛后按 F12，把 `usrhash` 那条粘进去，
一样能登录，完全不依赖调试接口。
