# v0.21.3：给登录对话框的两条轮询补用例，只防回退

## 为什么

「登录 X 岛」这个对话框里，验证码和账号密码登录都跑在后台线程：线程只能往队列里塞
结果，由主线程的轮询函数把它落到界面上。

- `LoginDialog._poll_form()`：验证码到手就挂到按钮上，失败就提示并允许重试；
- `LoginDialog._poll_login()`：登录成功收下 userhash 并关窗，失败弹一句解释并换一张验证码。

这两个函数在整包覆盖率里是整段空白（18 + 15 + 14 行没被执行过），而它们正好是
「验证码一直显示加载中」「点了登录没反应」这类反馈会落到的地方。

## 这版做了什么

只补测试，不改任何用户能看到的行为。`tests/test_window.py` 44 → 53（真 Tk）：

1. 验证码到手后挂到按钮上、按钮回到可用；
2. 验证码图坏了，按钮退回「刷新」而不是永远停在「加载中…」；
3. 验证码加载失败时弹出「加载验证码失败」并带上原因；
4. 账号、密码、验证码缺一项就提示；
5. 验证码还没加载完就点登录，提示稍候；
6. 登录成功：收下 userhash 并关闭对话框；
7. 登录失败：弹出错误、按钮复位，并换一张验证码；
8. 队列还空、后台仍在跑时，两条轮询都会再排一次（否则结果没人收）。

结果：这两个函数的业务分支现在全部走到，剩下未覆盖的只有「队列空 + 忙」的排队行
本身；只跑界面用例时 `xdao/gui.py` 的行覆盖由 61% 升到 63%。
