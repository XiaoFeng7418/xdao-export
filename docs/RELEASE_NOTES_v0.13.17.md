# v0.13.17：修「用浏览器登录」里第二种等不到登录成功

## 现象

在程序打开的浏览器窗口里用 X岛账号登录，页面已经进了用户系统、也能正常浏览，程序这边却一点反应
都没有：窗口上那句「已经等了 N 秒，还没在浏览器里看到登录」一直换数字，直到 5 分钟超时。也就是
「明明登录好了，程序收不到」。v0.13.15 专门修过一次这种情况（当前页找不到「应用」链接时自己去要
一次饼干列表），但真机上还是卡住。

## 原因

X 岛登录成功后不会直接下发 `userhash` 饼干，要再「应用一块饼干」，而站点这一步是**跳转式**的：
请求 `Member/User/Cookie/index.html` 拿回来的先是站点自己的「跳转提示」页 —— 实测是一张 1569 字节
的 HTML，`<title>跳转提示</title>`，正文写着「并没有权限访问…，请等待自动跳转」，落点放在
`<a id="href" href="…">` 上；跟着页面里那段 `setInterval` 每 1000 毫秒把 `#wait` 减一，3 秒后
`location.href = href` 自己跳过去（不是 HTTP 重定向，也不是 meta refresh）。真正种下 `userhash`
的是落地那一跳。

v0.13.15 的做法是在页面里用 `fetch` 复刻 `switchTo` / `export` 两个接口。`fetch` 拿回来的只是这张
提示页的 HTML：它既不执行页面里的跳转、也不会发出第二跳 —— 于是饼干罐里始终没有 `userhash`，
程序每 5 秒静默重试一次，直到超时；界面上看不出任何线索，那句等待提示每 15 秒被整句替换，
失败原因一闪就没了。

## 改法

- `xdao/browser_login.py`：删掉页面里的 `fetch` 脚本（`_APPLY_COOKIE_JS` /
  `build_apply_cookie_script`），改成**导航**：`build_find_apply_script()` 只读当前页的 DOM
  （不发请求），`fetch_leaf_cookie()` 按「跟着站点自己的跳转页走 → 去「饼干」页 → 导航到
  `switchTo/id/<id>.html` → 重读饼干罐 → 还不行就导航一次 `export/id/<id>.html` 从页面正文里抠」
  依次来，最多跳 `MAX_COOKIE_JUMPS` 次，每次导航等到文档加载完（`readyState == 'complete'`）再读。
  结果用 `LeafCookie(value, detail, navigated)` 返回：`detail` 是一句能直接显示给人看的话。
- 读饼干改成问**好几个地址**（站点根、饼干页、当前页）：`Network.getCookies` 只回「会发给这个地址」
  的饼干，只问一个会漏。
- `xdao/gui.py`：窗口上新增一行**常驻诊断**，把每一步的结论写出来（还在登录页 / 「饼干」页是空的 /
  列表写法没认出来 / 应用了却始终没有 `userhash`），超时提示也会带上最后试到的一步并写进运行日志。
  两条护栏：最多导航两次（之后只重读饼干罐，不会每几秒把用户的标签页弹一次）；用户还停在登录页时
  **绝不导航**（正在输验证码的人不该被弹走）。

功能、界面、导出结果与 0.13.16 一致，只有「用浏览器登录」这一条路变了。

## 真机核验

- 真机（真 Edge、真站点、匿名）跑新流程：起始页被认成登录页，`fetch_leaf_cookie` **一次都没导航**
  并回一句「这个窗口里还没登录（页面停在登录页）：先在里面登录 X 岛。」；把浏览器开到「饼干」页后，
  认出站点自己的「跳转提示」页（`kind='jump'`，落点 `Member/User/Index/login.html`），**导航跟着
  它跳**过去，最后落在登录页并回一句「跟着站点的跳转回到了登录页 —— 这个窗口里的登录没成。」，
  `navigated=True`；读饼干一次问 4 个地址（站点根 / 饼干页 / `nmbxd1.com` / 当前页）。
- 同一个地址站点有时直接 302 到登录页、有时回「跳转提示」页，两种都碰上了：前者按「还在登录页」
  处理（不导航），后者跟着跳；探针会清掉饼干重试，碰到跳转页为止。
- 没有可用账号，「登录成功后罐里真的出现 `userhash`」这一步没法在这台机器上重现；能验证的是
  **站点自己的跳转被浏览器真的走完了** —— 那正是 v0.13.15 断掉的地方。
- 用例：`tests/test_browser_login.py` 200 passed / 2 skipped（含新加的「跟着跳转落回登录页要报
  `navigated`」），`tests/test_gui_browser_login.py` 22 passed。
- 打包版 `--version` → 0.13.17；`--selftest --offline --check-browser` 仍是基线结论；
  升级 E2E 与 CI 照旧。
