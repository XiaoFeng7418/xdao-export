# v0.13.46：横条让位，对账行多两段

## 这一版改什么

1. **那条棕色横条挪到窗口底部，还能随手收起。** 上一版把它挂在窗口顶上，正好压住「我的饼干」
   列表第一排『应用』按钮 —— 它不挡点击（`pointer-events:none`），但挡眼睛，偏偏就挡在你要点
   『应用』的那一刻。现在它在窗底，压不到页面上的按钮；右端多了一个「×」，嫌碍眼点一下就收起
   （收起的只是横条，程序照旧在读这扇窗）。饼干拿到手的那一刻，横条会**自己摘掉**。
2. **说清一件事：程序不替你点『应用』。** 登录成功时站点会自己带上你当前的饼干，程序自己也走得通；
   点哪一行『应用』是「换一块饼干」的动作，挑哪一块是账号的事，得你自己定。横条与对话框都这么写。
3. **横条尾部带上端口。** 【窗口号 XXXX】管「这一趟尝试」、【端口NNNN】管「这一只罐」 —— 两张
   截图一对比，谁是谁当场对得上。
4. **「读罐对账」那一行多两段。** `哑窗=` 列出**调试端口已经哑掉**的自家窗口（那扇窗还在，只是
   程序问不进去）；`同罐进程=N` 报出正拿着这只资料目录的浏览器进程有几个 —— 多于 1 就说明还有
   第二个实例在共用这只罐（目录名一样、内存里的饼干罐各自独立，程序读的那只自然没有你登录挣来
   的饼干）。另外 `逐窗=` 改成**总写**：没有别的活窗口就写「没有别的活窗口」，免得再把
   「没别人」误读成「这一手没跑」。

功能、界面与导出结果跟 0.13.45 一样，变的是横条的位置、那句提醒的口径，以及对账行多出来的两段证据。

## 登录还是不行的话怎么自救

「读罐对账」那一行现在是三段证据（`逐窗=` / `哑窗=` / `同罐进程=`），几种形状对应几种毛病：

1. `逐窗=` 里别的窗口有 `userhash`、你在看的那扇没有 → 程序会点名叫你固定在那扇窗里登录；
2. `逐窗=没有别的活窗口`、`哑窗=` 里点了一扇 → 那扇窗的调试端口已经哑了，把它关掉重开一次；
3. `同罐进程=2` 或更多 → 还有第二个浏览器实例在共用这只资料目录，把多余的窗口全关掉再登；
4. 三段都没问题、这一罐里就是没有 `userhash` → 那一刻登录还没成，把整行贴回来。

懒得折腾就走对话框里的「直接粘贴饼干登录」：在你平时用的浏览器里登录 X 岛，按 F12 →
应用程序 → Cookie → `https://www.nmbxd1.com`，把 `userhash` 的值抄进去。
