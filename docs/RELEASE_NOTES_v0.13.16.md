# v0.13.16：公开内容里不再写「谁说的」

## 现象

仓库是公开的。README、发布说明、`使用说明.txt`、源码注释和用例的文档字符串里，有些句子是
先把「谁报的」写出来 —— 开头一句「有用户问：……」「有人反馈：……」「有人报过……」，后面才接
现象；更早的几版还把来源称作「这位用户 / 那位用户」，有的还带上日期。已经发布的 Release 正文
里也有同样的句子，而 Release 正文属于发出去就改不掉的历史，只能重新同步。

## 改法

- 仓库里剩下的句子改成直接写现象与规则：不复述来源的原话、不点来源、不带时间。
  涉及 `docs/RELEASE_NOTES_v0.13.14.md`（现象段与改法第一条）、
  `docs/RELEASE_NOTES_v0.10.2.md`（表格里的句式示例）、`xdao/gui.py`（两处注释）、
  `tests/test_window.py`（两处注释）、`tests/test_gui_entry.py`（文档字符串）、
  `README.md` 与 `packaging/使用说明.txt`（举的那个例子）。
- 六个已发布的 Release 正文按仓库里的 `docs/RELEASE_NOTES_v*.md` 重新推了一遍：
  v0.13.14、v0.13.7、v0.10.2、v0.6.1、v0.6.0、v0.3.0。其中 v0.13.7 / v0.6.1 / v0.6.0 /
  v0.3.0 的仓库文件在 v0.13.14 那一版就已经改成中性描述，只是 GitHub 上还挂着旧正文。
- 讲规矩本身的地方不在此列：`MAINTENANCE.md` 的「## 注释与文档的写法」要点出
  「有人报过…」「收到反馈说…」这类句式名 —— 那是在说规矩，不是引用谁。

功能、界面、导出结果与 0.13.15 完全一致。

## 真机核验

- 39 个 Release 正文逐条重扫：只剩上面那 6 个改过的，其余都没有「复述来源」的句子。
- 全仓逐文件复查：剩下的命中只有规则本身（`MAINTENANCE.md`、`README.md`、
  `docs/RELEASE_NOTES_v0.13.14.md`、`docs/RELEASE_NOTES_v0.10.2.md`）、泛用的产品用语
  （「用不了」「登不上」这类描述功能的词）和开发测量日期，没有任何来源的原话。
- 再按句子特征复查（原话里的片段）为 0 命中。
- 全量两轮测试：只动注释、文档字符串和说明文字，没有行为变化。
- 打包版 `--version` → 0.13.16；`--selftest --offline --check-browser` 仍是基线结论；
  升级 E2E 与 CI 照旧。
