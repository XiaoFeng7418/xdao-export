# v0.21.2：给界面队列轮询补用例（不吃用户行为，只防回退）

## 为什么

导出与「从串中挑选饼干」都跑在后台线程里，线程不能直接改界面——它只能往队列里塞消息，
由主线程的轮询函数把消息落到进度条、运行日志、选择窗口上：

- `App._poll_export()`：进度（`progress`）、日志（`log`）、收尾（`done`）三种消息；
- `App._poll_cookies()`：挑饼干成功就打开选择窗，失败就给一句解释。

这两条链路平时「看起来总是在跑」，一旦少写一行日志、或者失败分支漏了提示，用户看到的
只是「没反应」。上一轮覆盖率体检里 `xdao/gui.py` 是行覆盖率最低的一块（79%），而这两个
函数正好是其中价值最高、又不需要伪造复杂界面的部分。

## 这版做了什么

只补测试，不改任何用户能看到的行为：

1. `tests/test_window.py` 新增 3 条（真 Tk，窗口挪到屏幕外跑）：
   - 进度与日志消息被正确写到进度条文字与运行日志；
   - 「第一页里没有可选的饼干」提示发出，且「从串中挑选…」按钮复位；
   - 读取饼干失败时弹出「读取失败」并带上传来的原因。
2. 顺手记下一条断言坑：`ttk.Button.cget("state")` 返回的是 Tcl 的 index 对象，
   直接和 `"normal"` 比较恒为假，要先 `str(...)`。
3. 没有改动的部分：抓取、导出、合并导出、缓存、监控、字号、图片处理，行为都和
   v0.21.1 一致。
