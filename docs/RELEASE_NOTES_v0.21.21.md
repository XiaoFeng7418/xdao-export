# v0.21.21：抓页也能几页一起来了（可选项，默认不变）

设置里多了一个「同时抓页数」：默认 1，和以前完全一样；可以调到 2~6，让下载
网页这一步并发起来。产物与楼层顺序不变。

## 为什么

长串的主要耗时不在本地，而在等服务端响应：实测一条 79 页、1486 楼的串，只抓
页、导出 TXT，用了 346.9 秒，平均一页 4.4 秒；单页预热后也要 0.95~4.09 秒。
本地节流只有 0.08 秒一次，压不下去。既然时间是花在等上，那把「等」叠起来就
是最直接的提速，而且不改变任何产物内容。

## 改了什么

- 设置 → 网络新增「同时抓页数」（1~6，默认 1）；命令行是 `--page-workers N`；
- 只有「下载网页」并发：解析、写缓存、判断有没有到底仍按页号顺序做，成品与
  楼层顺序和串行时一致；
- 撞上站点限流（429 或提示太频繁）会自动退回一页一页抓，并在日志里说明；
- 默认值就是串行，不调就与上一版行为完全相同。

## 读数

- 测试：2718 项，本机 2711 通过、7 项真机用例默认跳过；
- 新增 42 条用例（抓取层 9、设置 14、命令行 9、界面 10）；
- 串行路径的产物逐字节不变，这一点有用例盯着。

## 升级建议

常抓长串的值得换这一版，把「同时抓页数」调到 3~4 试试。只抓短串可以不换。

## 附件

免安装包（Windows 64 位）：解压即用，不用装 Python、不用装依赖。换版本时
直接覆盖原目录即可，配置与缓存不在包里。

- `xdao-export-v0.21.21-win64.zip`（@package_info@）
- `xdao-export-v0.21.21-win64.zip.sha256`（SHA256：`@sha256@`）

下载后解压覆盖原目录即可；配置与缓存在 `%APPDATA%\xdao-export` 与导出目录里，不会被覆盖。
