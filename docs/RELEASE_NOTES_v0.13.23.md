# v0.13.23：一个标签页都不动 —— 领饼干彻底交给 HTTP，卡在哪一步也写进日志

## 现象

0.13.22 里登录本身是好的，可是**点「用浏览器登录」还是走不完**：复验的截图里，浏览器窗口停在
站点自己的「饼干切换成功!」页（写着「页面自动 跳转 等待时间： 1」），界面那行常驻提示一直是
「这个窗口里还没登录（页面停在登录页）：先在里面登录 X 岛。」，而运行日志里没有任何一句能
说明程序到底卡在哪一步。

## 原因

两件事叠在一起：

1. **那张跳转页会自己原地重载**。站点「饼干切换成功!」的落点写在页面里的 `<a id="href">` 上，
   成功时它是**空的**；页面脚本 `location.href = href` 拿到空串，等于把当前地址再载一次。
   0.13.17 起那几版让程序**导航**用户的标签页去「应用」饼干，于是标签页被留在这张永远重载的
   页上（看到的就是「一直无限跳转」），而 userhash 始终没种上。
2. **失败时说的话太少**。读浏览器饼干失败时被吞成空列表，「整罐里没有真会话」时那条 HTTP
   兜底又直接跳过 —— 两个分支都不出声，日志里只剩 CDP 那句「还没登录」，谁也判断不出 HTTP
   那条路到底跑没跑。

## 改法

- **界面层固定 `navigate=False`**：一个标签页都不碰，只读页面状态与整罐饼干。领饼干的正事交给
  HTTP（`apply_leaf_cookie_over_http()` → `XdaoClient.apply_cookie()`，从 v0.6.1 起就在线上跑的
  那套：认「跳转提示」页、跟着跳、从导出页正文里取 userhash、读 cookie jar 兜底）。三条导航护栏
  （次数上限、缓存间隔、上限提示）连同常量一起删掉 —— 不再有「次数」这回事。
- **每个轮询周期先报一句饼干罐**：`_jar_summary()` 写出「浏览器里的饼干：…（还没有 userhash）」
  「浏览器里现在没有任何属于 X 岛的饼干」「读不到浏览器里的饼干：<原话>」，只报**名字**，值一律
  不写（这行会跟着失败原因进运行日志，要能直接贴出来）。
- **失败原因带上诊断**：窗口关掉或出错时写进日志的那句话，现在会拼上「（<饼干罐诊断>；
  走 HTTP 领饼干：<站点或网络层的原话>）」（`_diagnosis()`）—— 下次再有类似问题，一张日志截图
  就能定位。
- `read_site_cookies()` 读不到就**抛**，调用方把这句话原样说出来（此前是吞成空列表）。

界面布局、导出格式、配置文件、命令行开关与 0.13.22 完全一致。
