# v0.17.6：失败时也把对账日志写进运行日志；两处测试稳定化

这一版不改任何行为，只补「看得见」和「测得准」两类东西。

## 为什么

上一版（v0.17.5）让候选表的每一次失败都留一行日志，但界面只在登录线程**成功**收尾时才
把这些行写出去。候选全部失败时走的是异常分支：只弹一个对话框，对话框一关什么都没留下 ——
最需要拿日志对账的那一次，恰恰是零记录。

另外两处本机/真机暴露的测试问题也一并修掉，免得以后每次在本机跑全量都要人工辨认。

## 这版做了什么

- **失败也留账**：候选取不出窗、整个登录线程收尾时，先在运行日志里写下「开窗前普查」的
  结论，再把每一扇没成的行（第几扇、哪个浏览器、开在哪份资料目录、为什么放弃）逐条写进
  运行日志与日志文件，最后才是那条错误提示。以前这些只存在对话框里。
- **README 去重**：同一段「多扇窗再出现时能对账」被粘了三遍，收成一条并把本版的补全写进去。
- **测试侧**：假浏览器的 `.cmd` 改写按系统代码页（仓库路径带中文时，本机十二条 PDF 用例
  不再因为批处理乱码而失败），并补一条回归用例钉住编码与行尾；GUI 登录用例不再真的拉起
  powershell 扫全机进程（以前每次两三秒，会把「启动失败要报可读错误」那条 20 秒预算挤爆）。
- 界面、导出格式、配置文件、命令行开关一律没动。

## 升级建议

直接用新版覆盖旧版即可，配置与导出结果都不变。如果还碰到「点一次弹出好几扇」，
用「保存…」把运行日志发出来 —— 现在连全部候选失败的那种情况也会留下对账行。
