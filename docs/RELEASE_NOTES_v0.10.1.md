# v0.10.1：把打包版登录窗口那条路也核了一遍

这一版**没有改功能**，只做了两件事：把 v0.10.0 那套修复在打包版的**登录窗口**上也量一遍，
并把量出来的事实写准。

## 为什么要单独量登录窗口

v0.10.0 修的是「打包版导不出 PDF」，靠的是启动浏览器时自动加 `--no-sandbox`。
当时的验证只覆盖了 PDF 那条路（无头渲染一次、拿到文件就结束）。而登录窗口走的是同一套
启动参数、但**用法完全不同**：浏览器要常驻、要连上调试协议、要真的把登录页加载出来 ——
「能启动」不等于「能用」。既然这一版的重点就是打包版能不能用浏览器，这条路不该靠推断。

## 量出来的结果（2026-10-01，同一台机器同一次运行里对照）

用一个专门打出来的冻结小程序，在真实的打包环境里各跑一轮：

| | 不加这个开关（旧版行为） | 加上开关（v0.10.0 起） |
|---|---|---|
| 浏览器进程 | **起来了**（调试端口也写出来了） | 起来了 |
| 调试协议 | 连得上 | 连得上 |
| 登录页 | **永远加载不出来**：地址与标题一直是空的，截图连试三次都是 `Internal error` | 地址 `login.html`、标题「用户登录 - User System - X岛揭示板」 |
| 截图 | 0 字节 | 27,910 字节 |

也就是说：**当年崩掉的是渲染器，不一定是浏览器进程。** 没有这个开关时，打包版的登录窗口
可能开得出来、看上去像在加载，但登录页永远出不来 —— 用户会觉得「点了没反应」。
旧的说明文字写的是「登录窗口也打不开」，方向没错、症状说粗了，这一版按实测改准。

## 你需要做什么

1. 如果你用的是 v0.10.0 的免安装包：**功能上不必升级**，登录窗口在那一版就是好的
   （同一个开关早就在两条路上都补了）。
2. 如果你之前下过更早的版本（v0.9.0 及以前）：请换成这一版，打包版才能正常导出 PDF、
   登录窗口也才能加载出登录页。
3. 想自己复核：在解压目录里开命令行执行 `xdao-export.exe --pdfdiag`，
   它会打印当前是不是打包运行、会加哪些浏览器参数。

## 下载

- `xdao-export-v0.10.1-win64.zip`（推荐，也是唯一的附件）：**免安装包**，解压后双击
  `xdao-export.exe`；包内附 `诊断写入.ps1` 与 `诊断写入-双击运行.cmd`。
- 单文件版自 v0.5.1 起不再提供：PyInstaller 的单文件版在含中文的路径下会直接报
  `Could not create temporary directory!`，属于打包器的限制，不是程序本身的问题。

## 已知边界（如实说明）

- **PDF 仍然需要本机装有 Chrome 或 Edge**（Windows 上基本都有）。没有浏览器、
  浏览器路径填错、或者被安全软件拦下时，程序会改存 HTML 并说明原因。
- **登录仍需要真人处理一次验证码**：视觉识别对 X 岛验证码的准确率太低（实测 3 张只认对
  一张半），所以不做自动登录，这一点没有变。
- 源码运行（`python main.py`）不注入这个开关，浏览器沙箱保持完好。
