# v0.13.38：不再动别人的端口文件；两扇窗时先看罐，有登录痕迹的那扇优先

## 该下哪个附件

下载 **免安装包** `xdao-export-v0.13.38-win64.zip`（解压后双击 `xdao-export.exe`，不需要装
Python）。同一页还挂着一份 `xdao-export-v0.13.38-win64.zip.sha256` —— 那是给上面这个包核对
用的校验文件，不是程序，不用解压。

## 这一版改什么

v0.13.37 把「看不见的旧窗」变成「点名收掉」，但还有一处病根没拔：程序每轮启动浏览器前，
会先把资料目录里那份 `DevToolsActivePort`（端口文件）**删掉**。当初的理由没错 —— 上次崩溃
留下的过期端口会让等待循环立刻「成功」、然后连到一个死端口。代价却一直没人看清：要删的
那个目录**可能正有一扇窗开着**。当候选落到程序自己那份持久资料目录
（`%APPDATA%\xdao-export\browser-profile`）、而它正被一扇窗用着时，这一删就删在了那扇窗
头上 —— 它从此读不到自己的端口，普查永远探不到它，程序只好再开一扇新窗：世上又多一个罐。
m38110 那个现场（你看得见的那扇在登录态、程序却读着另一扇的空罐）就是这两处病根叠起来的。

这一版补两件事：

- **不再删别人的端口文件**。改成「只认这次启动**之后**新写出来的那一份」：启动前先记下
  旧内容与旧时间戳，等待循环里只有内容变了或时间戳变了才当它是自己的端口。既不认死端口，
  也不碰任何不属于这次的运行的文件。顺带把「被接管」说清楚：真机实测（2026-10-04，在
  一个还开着窗的持久资料目录上再走一次启动），浏览器会以**退出码 0** 干净退出 —— 那不是
  崩溃，是它把要开的页面交给了已经在跑的那一扇；日志现在会点明这一句，不再让人往
  「资料目录坏了」猜。
- **多扇活窗时先看罐，有登录痕迹的那扇优先**。开窗前探到**多于一扇**还活着的程序窗口时，
  先各自开一条只读短会话看一眼它的饼干罐（只读、不导航、不点任何按钮，浏览器窗口连闪都
  不会闪），罐里留着 `userhash` 的那一扇优先接手，普查句一并点名：「其中 N 扇的罐里留着
  登录痕迹（××），先接这一扇」。以前是按「谁后开的」挑，那跟「谁登录过」毫无关系 ——
  这正是「F12 里明明有饼干、程序说没有」的来源。探到的罐里都没有登录痕迹时不重排（没有
  判据就别自作主张），只有一扇窗时也不做这一步，不拖慢最常走的路。

界面布局、导出格式、配置文件、命令行开关都没动。

## 登录不行的话，这一版怎么自救

1. 看运行日志两行：`开窗前普查：…`（探到几扇、其中几扇罐里有登录痕迹、接手了哪一扇）和
   `读罐对账：…接=端口N…`。两处点名的窗口是不是你肉眼登录的那一扇，一眼能对上。
2. 想回到全新状态：关掉所有程序开的登录窗口（新版会把端口失联的残留进程先收掉），再把
   `%APPDATA%\xdao-export\browser-profile` 文件夹删掉，重新点「用浏览器登录」。
3. 急用不等程序抓：在你登录成功、刷新都不弹回登录页的那扇窗里按 F12 →「应用程序/存储」→
   Cookie，抄出 `userhash=…`，用主界面的「直接粘贴饼干登录」贴进去。

## 下载后核对一下

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.38-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.38-win64.zip.sha256
```

两行的字符串一样就是原件。
