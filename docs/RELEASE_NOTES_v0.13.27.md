# v0.13.27：「写不进去」说得出原因，「打开目录」真的会去开

这一版修两处「结论没有下文」的地方，并按要求把「用途与声明」补全。

## 一、探针误报「写不进去」，还把原因吞了

0.13.26 报「导出目录仍旧是不可写」。日志里那句话是：导出目录（文档下的自建文件夹）
写不进去，连 `%LOCALAPPDATA%\xdao-export\导出` 这个兜底位置也不行 —— 可那台机器磁盘没满、
目录既不是只读、也没有被安全软件拦住：同一次导出照样抓页、下载图片、把成品写了出来。

错的是探针。它只探一次，失败就下结论，而且 `except OSError` 把系统原话丢掉了。现在：

- 探针有**两个名字**（`xdao-write-test.tmp` 与 `xdao-write-test.txt`），任一能写就算能写
  —— 探针名被安全软件单独挡掉，是这个项目 2026-09-30 就吃过一次亏的老问题；
- 探不通时把「哪一步、系统怎么说的」**原样**写进运行日志，例如
  `写 xdao-write-test.tmp 时：[Errno 13] Permission denied`；
- 连兜底位置也探不通时，措辞不再像硬失败，而是明说：这一趟仍然写在你选的目录里，
  真写不进去会在导出时报出真实的文件名与错误。

## 二、「打开目录」只弹一个写着路径的框

同一个现场：点「打开目录」，弹出来的是一个只有路径的提示框。因为那段代码是
`try: os.startfile(目录) / except: 弹路径`，而 `os.startfile` 在那台机器上被系统拒了 ——
于是「系统不让程序拉起资源管理器」这个真正的原因被吞掉，看起来像按钮本身坏了。

现在按三种方式依次试：`os.startfile` → `explorer` → `explorer /select,`。每一次失败都记进
运行日志；三种都不行时，把三步的原因一起写进提示框，并提示可以把路径粘到资源管理器的地址栏。
另外，目录建不出来（路径不可创建）时当场说清，而不是炸在 Tk 的回调里。
