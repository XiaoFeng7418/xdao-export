# v0.13.53：保存失败不再谎报成功

## 这一版改什么

上一版真机上出现过一次自相矛盾：运行日志写着「登录成功，饼干已保存。」，而配置文件
`%APPDATA%\xdao-export\config.json` 的修改时间停在两周前、里面的 `userhash` 是空的 ——
重启程序当然还要重新登录。原因是两层：

1. `AppSettings.save()` 把写盘异常整个吞掉了（`except Exception: pass`），写不进去也一声
   不响，界面照着报成功；
2. 那次运行里那个目录确实写不进去（程序是从一个被限制写入的目录里启动的）。

这一版把第一层改掉：

- `AppSettings.save()` 现在返回「写没写成」；界面按结果说话：写成 → 「登录成功，饼干已保存。」；
  写不成 → 运行日志明说「设置没能写进 <配置文件路径> —— 这次的改动只在本次运行里有效，
  重启就没了」，登录那一次还会弹一个提示框，把路径、常见原因和可行的做法写清楚；
- 「设置」对话框保存时同样按结果说话：只有真的写进文件才记「设置已保存」。

## 关于受限目录

某些环境会把「从某个目录里启动的程序」限制成只能写那个目录：程序能启动、能读，但往
`%APPDATA%`、`文档`、甚至别的盘写都会被拒（`[Errno 13] Permission denied`）。表现就是
导出目录被判「写不进去」、配置也存不下来。这一版不能改变系统的限制，但会把它说清楚 ——
遇到这种情况，把**整个程序文件夹**挪到不受限的位置即可（实测同一个包在受限目录里自检报
2 处「不行」，挪出来全部正常；另用一个极小的对照程序验证过：同一个 exe 放在受限目录里连
它自己的临时目录都建不出来，放在别处则四个目录全部「能写」）。
