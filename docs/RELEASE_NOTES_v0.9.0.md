# v0.9.0：监控列表可以备份和还原了

这一版给「串监控」加了一个出口：列表能**导出成一个文件**（方便备份、换机器、重装后恢复），
也能**从文件导回来**。列表不会再因为重装系统、换电脑或者手滑清掉配置而全部丢掉。

## 这一版改了什么

### 1. 监控窗口里多了「导出列表 / 导入列表」

打开「串监控」，列表下面多了一行：

- **导出列表**：把当前监控的串存成一个 `.json` 文件（默认文件名带日期，
  例如 `xdao-export-监控列表-20261001.json`）。列表为空时不弹保存框，直接提示，免得存出一个空文件。
- **导入列表**：选一个文件导回来，**合并进现有列表**，不会把原有的条目冲掉。
  文件里有认不出的条目时会逐条告诉你原因，能认的照常导入 —— **坏一条不会毁掉整份文件**。

导出的文件是纯文本 JSON（中文不转义），你可以直接打开看、手改、或者贴给别人。

### 2. 命令行也能导入导出（方便批处理与脚本）

```
--watch-export 文件.json        把当前监控列表导出到文件
--watch-import 文件.json        从文件导入（合并，不覆盖原有条目）
--watch-import-replace          导入前先清空现有列表（要跟 --watch-import 一起用）
```

这两个动作不联网、不会启动图形界面。参数写错（比如两个一起给、只给 `--watch-import-replace`、
文件不是有效的列表文件）都会打印中文说明并以退出码 2 结束，不会静默忽略。

### 3. 文件里存什么、不存什么

存的是**「怎么监控」**：串号或网址、抓取范围、导出格式、饼干筛选、图片处理方式。

**不存「监控到哪儿了」**：上次检查时间、已导出的楼层、上次的报错这些状态都跟着本机的缓存目录走。
把它们一起搬走，导进来的机器会以为"这个串已经导出过了"，第一轮该出的新楼反而不出。
所以换机器之后，导入的列表会从当前进度重新核对一次。

### 4. 顺手修掉的问题

- **监控窗口底部的按钮会被裁掉**：导入/导出按钮原先挤在「添加 / 移除 / 间隔 / 校验」那一行右边，
  窗口宽度不够时整条被裁到窗口外 —— 控件都在，用户却看不见。现在它们单独占一行，
  窗口高度也相应加了一行（这条是截图才发现的，自动化用例当时全是绿的）。
- **`--watch-import-replace` 会把列表清空**：如果文件里的条目你**现在就在监控**
  （同一个串、同样的设置），它会被算成"已经有了"而从替换结果里漏掉 ——
  于是一份「想把列表换成文件里那些」的替换，可能落成一条不剩。
  现在这些条目会保留下来，命令行也会把它们印成「保留」而不是「跳过」。

## 你现在该怎么做

1. 下载下面的免安装包，解压，双击 `xdao-export.exe`。
2. 备份监控列表：「串监控」→「导出列表」→ 存到你想放的地方（网盘、U 盘都行）。
3. 换机器或重装之后：装好新版 →「串监控」→「导入列表」→ 选那个文件。

之前的版本（包括 v0.8.0）的配置与缓存都不用动，直接覆盖使用即可。

## 已知边界（如实说明）

- **导入是合并，不是替换**：同一个串按不同格式或不同范围各监控一份是允许的，
  所以重复导入同一个文件不会产生重复条目，但也不会删掉你后来加的条目；
  真要清空重来请用 `--watch-import-replace`。
- **导出文件不含监控进度**（理由见上），换机器后第一轮检查会按当前进度重新核对一遍。
- **串号以文件为准会出问题，所以程序按文件里的网址重新认一遍串号**：
  这样手改文件里的串号也能正确生效，不会出现"明明有新回复却一直说没更新"。
- **登录仍需要真人处理一次验证码**：视觉识别对 X 岛验证码的准确率太低（实测 3 张只认对
  一张半），所以不做自动登录，这一点没有变。
- **PDF 导出仍然需要本机装有 Chrome 或 Edge**（Windows 上基本都有），详见 `MAINTENANCE.md`
  的「已知限制」一节。
