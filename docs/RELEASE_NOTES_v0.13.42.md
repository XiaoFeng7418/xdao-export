# v0.13.42：读饼干罐多问一条路 —— F12 里看得见的那条，程序也能读到了

## 这一版改什么

这一版治的是**「F12 里明明有一条 userhash，程序却说罐里没有」**。

**一、读罐多问一条路：`Storage.getCookies`**

程序以前读饼干罐走三条路：

1. 按地址读 —— `Network.getCookies`；
2. 整罐读 —— `Network.getAllCookies`；
3. 页面脚本读 —— `document.cookie`。

浏览器对带 `Partitioned`（分区）标记的饼干（CHIPS）**只交给第四种问法** ——
`Storage.getCookies`，也就是 F12 里「应用程序 → Cookie」那个面板用的那条路。前两条
`Network` 读法对这类饼干一律装看不见，`document.cookie` 又看不见 HttpOnly 的它。
结果就是你看到的样子：同一扇窗的 F12 里躺着一条 `userhash`，程序的对账行却写
「全罐=2、原始userhash=无」。

这一版起，**整罐读改成两条路的并集**（`Network.getAllCookies` + `Storage.getCookies`）：

- 同一块饼干只算一次；分区键不同的两块**不会被合成一块**；
- 只有两条路都失败才算读失败，一条成一条败就用成功的那条。

**二、对账行多一段「存储读=」**

`读罐对账` 那一行现在会把 `Storage.getCookies` 看见的名单**单独列一段**。于是下一张
截图就能分清两种完全不同的毛病：

- **「存储读=」有、「整罐读=」没有** → 分区饼干那条已知盲区（这一版已经补上）；
- **两边都没有** → 是**读错了罐**，该去查「程序接的是哪扇窗」（配合同行早就有的
  `罐=…`、`接=端口…`、以及窗口横幅末尾【窗口号】）。

照样只报名字与属性，值一个字符都不写进日志。

**三、路线图：删掉「无人值守登录」**

按用户 2026-10-04 的定案，这一条**从路线图里删掉**（验证码必须真人认一次，实测视觉模型
对 X 岛的验证码识别率太低）—— 不列成待办，以后也不再提。

界面、导出格式、配置文件、命令行开关都没动。

## 登录不行的话，这一版怎么自救

1. 更新后重新点「用浏览器登录」，登录成功那一扇窗里按 F12 →「应用程序/存储」→ Cookie，
   看有没有 `userhash`；同时看主界面「运行日志」里最新的 `读罐对账` 一行：
   `存储读=` 里有没有 `userhash`。
2. 如果 `存储读=` 与 `整罐读=` **都没有** `userhash`：那是读错了罐 —— 把那一行连同窗口
   横幅上的【窗口号】一起发出来，就能定位程序接的是哪扇窗。
3. 急用不等程序：在登录成功、刷新都不弹回登录页的那扇窗的 F12 里抄出 `userhash=…`，
   用主界面的「直接粘贴饼干登录」贴进去。
