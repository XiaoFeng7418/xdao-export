## 本次更新

修一个很烦人的问题：**导出目录（或缓存目录）不可写时，整个导出直接失败**。
现在缓存写不进去不再是致命错误——它会自己换个能写的地方，导出照常完成。

### 问题：导出目录不可写 = 白抓一场

从 v0.2 加了本地缓存之后，程序会在导出目录下建 `.cache`。如果那个位置不允许写
（只读介质、权限受限的目录、被安全软件锁住的盘、程序跑在受限环境里），程序会在
**开始抓取之前**就报错退出：

```
失败：缓存目录不可写：<盘符>\X岛\.cache
[Errno 13] Permission denied: '<盘符>\X岛\.cache\xdao-write-test.tmp'
```

这解释了为什么「旧版能用、新版不能用」：0.1.0 根本没有缓存层，只往导出目录写文件，
所以不受影响；0.2 以后的版本把缓存当成了必须可用的前置条件。**缓存只是加速手段，
不该挡住宿主功能。**

### 现在会怎么做

缓存目录写不进去时，按顺序自动换地方（用户设置 → `%LOCALAPPDATA%\xdao-export\.cache`
→ `%APPDATA%\xdao-export\.cache` → 系统临时目录），并且**明确告诉你换了地方**：

```
注意：缓存目录 <盘符>\X岛\.cache 写不进去，本次改用 C:\Users\你\AppData\Local\xdao-export\.cache。
想固定下来可以在设置里改「缓存目录」。
```

- 换过去之后**断点续传、图片缓存照常工作**（实测：换到兜底目录后，`pages/` 与
  `threads/` 状态文件正常落盘，第二次导出依然是「下载 0 页」）；
- 只有当**所有**候选位置都写不进去时，才会像以前一样报错，而且是一个请求都不发就报错；
- 界面上的「缓存信息」行显示的是**真正在用**的目录，并在换过之后附上说明；
- 命令行表头同样显示真实目录，避免「显示的目录和实际用的不是同一个」。

### 如果真的一个地方都写不进去

关掉缓存即可，导出功能完全不受影响：

```powershell
xdao-export.exe 50000001 -o <盘符>\X岛 --no-cache
```

源码运行则是 `python main.py 50000001 -o <盘符>\X岛 --no-cache`。

### 其它

- 新增 `can_write_dir()` / `cache_dir_candidates()` / `resolve_cache_dir()`，
  缓存层不再把「探测失败」当成致命错误；
- 测试从 219 项增至 **223 项**，新增「换地方继续」「首选能写就不换」「候选顺序不重复」
  「全写不进去才报错且不发请求」四个用例。
