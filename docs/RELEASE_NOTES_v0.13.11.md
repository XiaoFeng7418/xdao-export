# v0.13.11：启动时把以前留下的临时资料目录扫掉

## 现象

从 v0.13.9 起，「用浏览器登录」不再复用配置目录里那个旧资料目录，而是**每次开一个全新的
临时目录**（系统临时目录下），关掉登录窗口后自动删掉；v0.13.10 又把「起不来的那次」也补上了。

这两条都靠**程序自己收尾**。可程序要是被强杀 —— 任务管理器结束进程、重启、断电、被安全软件
拦下 —— 收尾那一步就没机会跑，那些目录会一直留在系统临时目录里。修 v0.13.10 的时候在这台
机器上量到过 147 个 `xdao-export-browser-profile-*`，其中 123 个是空壳。

## 改法

程序启动后**在后台**（不耽误开窗）扫一遍系统临时目录，三条全中才删：

1. 在系统临时目录下、名字是程序自己建的：`xdao-export-browser-profile…`（登录窗口那份），
   以及 `xdao-browser-check-…`（`--selftest --check-browser` 自检那份）；
2. 目录的修改时间比一小时还老 —— 刚建出来的多半是另一个实例正开着登录窗口；
3. 那个目录里的调试端口**没人答话**。浏览器还开着它时端口一定答话（程序被强杀时浏览器自己
   会活下来），答话就跳过：绝不会把活浏览器脚下的目录抽走。

删不掉的留着下次启动再说，不影响开窗，也不影响导出。

顺带修掉一处：自检那份临时资料目录以前收尾只删一次、删不掉就算了（浏览器正咽气时文件还被
占着），这台机器上就攒了 5 个；现在它也算「程序自己建的」，走同一套带重试的删除（每 0.25 秒
重试、最多 3 秒）。

## 真机核验

- 造一个旧的登录目录、一个旧的自检目录、一个刚建的目录和一个别人的目录：旧的删掉、刚建的与
  别人的留着。
- 真起一个浏览器让它开着新目录：判据（端口答话）为真，即使把年龄门槛设成 0 也不动它；
  关掉之后目录立刻消失，收尾时系统临时目录里 0 个残留。
- 源码跑 `--selftest --offline --check-browser` 之后，`%TEMP%` 里 0 个 `xdao-browser-check-*`。
