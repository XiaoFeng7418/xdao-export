# v0.13.47：去看看同一只浏览器里别的「罐」

## 这一版改什么

还是冲着同一件事：F12「应用程序 → Cookie」里明明有的 `userhash`，程序就是读不到。这一版不再
往读法上找，而是换了个方向 —— **去问同一只浏览器里别的「罐」**。

1. **同一只浏览器内部还能有好几份罐。** Chromium 的饼干是按「浏览器上下文」分开存的：无痕窗口
   一份、Edge 的「工作区」一份，互相看不见。同一只浏览器、同一个调试端口、同一扇挂着横条的窗，
   程序按页面读到的也可能是**默认那一份**，而你 F12 里看到的是另一份。这一版专门连上**浏览器
   端点**（只有它答得出「这只浏览器里有几份罐」），把每一份都读一遍。
2. **「读罐对账」多一段 `别路=`。** 只在真有额外那份罐时才出现，形如
   `别路=上下文3f2a1b：PHPSESSID、userhash（userhash 在这一份里）`。真在那里面认出了
   `userhash`，程序会**直接拿来用**、接着往下走，并提醒你「以后固定在程序盯着的那扇窗里登录」。
3. **等够时间还是没拿到，就留一份「读罐详单」。** 路径会打在运行日志里（形如
   `…\Temp\xdao-读罐详单-XXXX.json`）：里面有域、路径、分区键、哪一份罐，也有饼干的值本身。
   **只在本机**，贴给别人之前请自己掂量一下 —— 对不上账的时候，把这份文件（或其中一段）发出来，
   就能一次看清差在哪一条读法、哪一份罐。

功能、界面与导出结果跟 0.13.46 一样，变的是「读不到」时程序还能去哪儿多问一句。

## 登录还是不行的话怎么自救

「读罐对账」那一行现在有四段证据（`逐窗=` / `哑窗=` / `同罐进程=` / `别路=`）：

1. `别路=` 里那一份有 `userhash` → 程序会自己拿来用；麻烦你下次固定在那扇窗里登录；
2. `逐窗=` 里别的窗口有 `userhash` → 同上，程序会点名叫你固定在那扇窗里登录；
3. `逐窗=没有别的活窗口`、`哑窗=` 里点了一扇 → 那扇窗的调试端口已经哑了，把它关掉重开一次；
4. 四段都没问题、这一罐里就是没有 `userhash` → 那一刻登录还没成：把整行贴回来，顺手把日志里那份
   「读罐详单」也发出来（记得先自己看一眼值）。

懒得折腾就走对话框里的「直接粘贴饼干登录」：在你平时用的浏览器里登录 X 岛，按 F12 →
应用程序 → Cookie → `https://www.nmbxd1.com`，把 `userhash` 的值抄进去。
