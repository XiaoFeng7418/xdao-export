# v0.13.41：反复起不来的资料目录自己让位；收尾不再动还开着的窗

## 该下哪个附件

下载 **免安装包** `xdao-export-v0.13.41-win64.zip`（解压后双击 `xdao-export.exe`，不需要装
Python）。同一页还挂着一份 `xdao-export-v0.13.41-win64.zip.sha256` —— 那是给上面这个包核对
用的校验文件，不是程序，不用解压。

## 这一版改什么

这一版治的是**一份坏掉的资料目录，会把之后的每一次尝试都毒死**；顺带堵掉一处「收尾动了
别人还开着的窗」的隐患。

**一、死资料目录自己改名让位**

程序那份持久的资料目录是 `%APPDATA%\xdao-export\browser-profile`，里面存着你的登录状态，
所以它一直是被保护的对象 —— 但也因此，一旦它坏掉（被锁住、被安全软件拦下写不进去、
上一次强杀留下的文件坏了），程序**每次都还会拿它去试一次**，撞墙、再换干净的目录。
表现就是：每回登录都要先卡一下，日志里一行行都是同一份目录起不来。

这一版给它记一笔账，记在目录自己里面（`login-failures.txt`）：

- **连着两次**「刚起来就退出」才动手。偶尔一次可能是安全软件正忙，不算 —— 只有连着
  失败才叫「这份目录坏了」。
- 够两次就把整个目录改名成 `browser-profile.damaged-<年月日-时分秒>` **留在原地**
  （重名就再加 `-2`、`-3`…）。里面的登录状态**一个字节都不动**：想留着自己看就留着，
  想删就删 —— 改名后的名字不匹配任何清扫规则，程序**不会**替你删。
- 下一次登录自然会用一份全新的目录，不会再撞同一堵墙。
- 有一次成功启动，账就清零（账跟着最近的事实走）。

**二、收尾前先问一次端口：还开着的窗，连目录一起留着**

`%TEMP%` 里那些自家临时资料目录，收尾时是要删的（一次登录几十上百 MB）。但真机上量到过
一种情况：在一份**已经开着窗**的资料目录上再启动一次（第二个实例会把页面交给第一扇窗、
自己退出），收尾就会把那份目录连那扇还开着的窗一起带走 —— 写这个版本的探针脚本时，它
真的一次就删掉了那扇窗的端口文件。

这一版起：删之前先问一次调试端口，**端口还答话的目录一个字节都不动**，留在清单里下次
收尾再问。宁可漏一份目录在 `%TEMP%` 里（那本来就在系统的临时目录里），也不能动用户正
开着的窗。

**真机验证**（2026-10-04，本机 Windows + 真 Edge，无人值守跑完 9 项）：真起一扇窗拿到端口；
端口文件两行与程序用的 WebSocket 地址对得上；进程侧普查认得该目录、端口答话、端口普查也
列到；在一份**还开着**的持久目录上再启动，报的是「刚起来就退出了（退出码 0）…就有一扇窗
开着」，端口文件一个字节没动、旧窗还活着；改名让位真在配置目录风格的目录上跑通（内容还在、
两个清扫函数都扫了它一遍、都没删）；杀掉那一扇窗后端口立刻失联；最后这份座位带也验了 ——
在还开着窗的临时目录上再启动一次，目录、端口文件、那扇窗全都完好。

界面、导出格式、配置文件、命令行开关都没动。

## 登录不行的话，这一版怎么自救

1. 如果你以前的资料目录已经坏了，这一版**第一、二次尝试仍然会失败**（它要连着两次才
   认定「坏了」）。第二次失败后你会看到一段话，告诉你目录已经被改名留在原地、下次会用
   一份全新的。**再点一次「用浏览器登录」**就会用新目录。
2. 想立刻回到全新状态：关掉所有程序开的登录窗口，把 `%APPDATA%\xdao-export\browser-profile`
   文件夹删掉（带上那些 `browser-profile.damaged-<时间戳>`），重新点「用浏览器登录」。
3. 急用不等程序：在你登录成功、刷新都不弹回登录页的那扇窗里按 F12 →「应用程序/存储」→
   Cookie，抄出 `userhash=…`，用主界面的「直接粘贴饼干登录」贴进去。

## 下载后核对一下

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.41-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.41-win64.zip.sha256
```

两行的字符串一样就是原件。
