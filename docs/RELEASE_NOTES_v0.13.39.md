# v0.13.39：配置目录里那族没人收的备用资料目录，现在会自己收干净

## 该下哪个附件

下载 **免安装包** `xdao-export-v0.13.39-win64.zip`（解压后双击 `xdao-export.exe`，不需要装
Python）。同一页还挂着一份 `xdao-export-v0.13.39-win64.zip.sha256` —— 那是给上面这个包核对
用的校验文件，不是程序，不用解压。

## 这一版改什么

程序启动浏览器时会准备一份「资料目录」（profile，浏览器把登录状态都存这里面）。首选是配置
目录里那份**持久的** `%APPDATA%\xdao-export\browser-profile`；这份用不了时，它会**当场再建
一份备用的**接着试，名字长这样：`browser-profile-<进程号>-<时间戳>`。

问题就出在这个备用目录上：以前只有建在系统临时目录（`%TEMP%`）下的那一族会被记账、收尾时
删掉，**建在配置目录这一级的这一族没人收**。程序要是被强杀（任务管理器结束进程、停电、安全
软件拦下），它们就一直躺在用户的配置目录里没人管。真机 2026-10-04 复查时量到三个遗留：
`browser-profile-12268-1790850954`（96 个文件 / 5.6MB）、
`browser-profile-12268-1790850956`（66 个文件 / 6.3MB），以及持久目录**里面**那份
`browser-profile\_new`（121 个文件 / 11.2MB）。

这一版补两件事：

- **收尾时一并删掉**。启动用的资料目录只要是我们自己建的（系统临时目录那一族、配置目录里
  `browser-profile-<进程号>-<时间戳>` 这一族、以及持久目录里的 `_new`），都记进清单，程序
  正常收尾时一起清掉。用户那份持久的 `browser-profile` **永远不记、永远不删** —— 那是他下次
  还要用的登录状态。
- **开机顺手扫一遍**。程序启动时会看一下配置目录，只删**严格对得上名字**（两段都必须是纯
  数字）、**年龄超过一小时**、而且**调试端口没人答话**的目录；三条全中才动手。名字认到这么
  死是为了绝不误伤：持久目录、用户自己起的名字、任何别的文件夹，一个都不碰。真机验证：
  这一版在出问题的机器上跑一次，正好收掉上面那三个（5.6MB + 6.3MB + 11.2MB），持久目录里
  的 1084 个文件、88.0MB 一个字节没动。

界面布局、导出格式、配置文件、命令行开关都没动。

## 登录不行的话，这一版怎么自救

1. 不用再手动去配置目录里删那一堆 `browser-profile-<数字>-<数字>` 文件夹了 —— 这一版开机
   自己会收（需要它们超过一小时、且确实没浏览器在用）。
2. 想回到全新状态：关掉所有程序开的登录窗口，再把 `%APPDATA%\xdao-export\browser-profile`
   文件夹删掉，重新点「用浏览器登录」。
3. 急用不等程序抓：在你登录成功、刷新都不弹回登录页的那扇窗里按 F12 →「应用程序/存储」→
   Cookie，抄出 `userhash=…`，用主界面的「直接粘贴饼干登录」贴进去。

## 下载后核对一下

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.39-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.39-win64.zip.sha256
```

两行的字符串一样就是原件。
