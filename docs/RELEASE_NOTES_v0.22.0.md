# v0.22.0：看得见还剩多久，也知道缺了什么

这一版把「不知道还要等多久」和「不知道缺了什么」这两件事一起补上：批量导出会估
剩余时间；有串没抓全时，导出目录里会留一份清单。另外抓页默认改成两页一起要数据，
高分屏上界面也不再被拉伸。

## 为什么

- 长串导出动辄十几分钟，界面只显示「[3/12] 网址」，不知道还要等多久；
- 缺页、缺图只写在运行日志里，程序一关就没了。老用户拿到半份成品，还以为抓完了；
- 实测一条 79 页、1486 楼的串，只抓页、导出 TXT 用了 346.9 秒，平均一页 4.4 秒，
  本地节流只有 0.08 秒一次 —— 时间几乎全花在等服务端回话上，那两页一起等就快一倍。
- Windows 缩放 125% / 150% 时，原来的窗口是被系统按位图拉伸的，字发虚。

## 改了什么

- 批量导出：进度行后面带「约剩 X」；命令行每个串开头报「还剩 N 个串，按当前速度约 X」，
  第一个串没样本时不估；
- 导出报告：有串缺页或缺图时，导出目录里落一份 `导出报告-时间.txt`，写明串号、标题、
  成品名、楼层数、缺页原因与前 20 张没下到的图；干净的导出不留文件；
- 抓页默认 2 路（设置 → 网络可调 2~6，命令行 `--page-workers N`）；只并发下载网页，
  解析与写缓存仍按页号顺序，成品与楼层顺序不变；撞限流自动退回串行并记住这次退回；
  手动选过 1 的配置不会被动；
- 高分屏：按系统 DPI 画界面，间距、左栏宽度与窗口尺寸跟着放大，字号仍由「字号」
  下拉框单独控制。

## 读数

- 测试：2763 项，本机 2756 通过、7 项真机用例默认跳过；
- 新增 45 条用例（抓取层 0 改动只改默认值断言、设置 2、界面 6、命令行 5、
  导出报告 6、时长文案 18、DPI 10）；
- 默认两路抓页下，产物与串行时逐字节一致，这一点有用例盯着（Barrier 证明真并发）。

## 升级建议

都值得换。常抓长串的可以再把「同时抓页数」调到 3~4；只想恢复从前的逐页抓法，
把它改回 1 即可。
