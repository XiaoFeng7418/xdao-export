# v0.21.11：给界面里几个「后台动作」的成败两分支补用例

这一版不改任何用户能看到的行为——只补测试，把三个后台线程内层函数的成功与失败两条路都钉进用例里。

## 为什么

界面里有一类函数，是点了按钮之后在后台线程里跑的那一小段：刷新验证码、提交账号密码、从串里读饼干。它们只有五行十行，但**成功与失败都得把结果放回队列**——放错了，界面就一直转圈，用户看到的是「点了没反应」。

此前的用例测的都是「队列里的东西怎么显示」，没人测「线程往里放了什么」。这一版补的就是后者。

## 这版做了什么

`tests/test_gui_entry.py` 153 → 160，七条：

- 验证码取不到：队列里是 `("form_error", 原文)`，界面据此弹「加载验证码失败」。
- 验证码取到了：队列里是 `("form", form)`。
- 登录抛异常：队列里是 `("fail", 原文)`。
- 登录成功：把「邮箱 / 密码 / 验证码 / 表单 hash」四个参数原样交给客户端，并把 userhash 放回队列。
- 从串里读饼干三种：站点回一段文字（当错误处理）、回 `success=false`（把站点给的原因带出来）、正常解析出帖子。

做法是把模块里的 `threading` 换成一个「start() 就地跑完」的替身，于是后台函数变成同步调用；对象用 `object.__new__` 造，只摆上队列、客户端与按钮替身——不开窗口、不起进程、不联网。
