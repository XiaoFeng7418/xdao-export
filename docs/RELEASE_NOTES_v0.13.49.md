# v0.13.49：一次「打扫屋子」的版本（功能与界面不变）

## 这一版改什么

这一版**不新增功能，也不改操作方式**：导出结果、文件名规则、界面、命令行开关都跟 v0.13.48 一样。
改的是屋子内部 —— 按你 2026-10-07 要的那份《架构评审》报告里的问题清单（`xdao-export-架构评审-2026-10-07.md`），
先把 §7.1 的三件事与 §6 里风险最低的几项做掉。

1. **目录与写权限的判断下沉到 `xdao/paths.py`。** 「这个目录写不写得进去」过去同时被缓存层、导出器、
   自检三处实现（还造成 `cache → exporters._shared` 这种反向依赖）。现在只此一份，改一处不会漏掉另外两处。
2. **五个导出器（HTML / PDF / TXT / Markdown / EPUB）立了共同底座 `xdao/exporters/base.py`。** 显示名、
   扩展名、保存提示、写盘方式是类属性与模板方法；`create_exporter` 那个「挨个参数试着降级」的五层
   `TypeError` 阶梯删掉了 —— 过去它掩盖了真实签名错误。
3. **产品名、仓库地址、压缩包名、启动器名、版本号读取收成 `xdao/appinfo.py`；「怎么问 GitHub」（取令牌、
   代理、退避重试、git 子进程）收成 `xdao/github_api.py`。** 四个打包/发布脚本共用一份，`updater.py`
   那条反向 import 也消失了。脚本各自的退避参数与提示流向**故意没有统一**（用钩子区分，行为照旧）。
4. **删掉确认没人再用的旧代码：** 整个 `xdao/fetcher.py`（122 行）、缓存里两个零引用函数、
   一个零引用的超时常量。顺手更正：报告里点的另外三处（`client.import_userhash`、`main._CONSOLE_HINT_FLAGS`、
   `pdf.is_frozen`）**其实都在用**，逐条 grep 复核后保留 —— 更正记在报告的附录 B 里。
5. **两处重复合并、一类判断修掉：** 回复数的读法只剩 `client.reply_count` 一处；监控目标写进文件时统一
   写 `hashes`（老配置文件仍读得进）；`client.py` 里那段恒假的代理判断换成直接装配。
6. **修掉一条在忙机器上会假红、也会假绿的界面用例：** 等待时间从 5 秒放宽到 20 秒。2026-10-07 那次全量里，
   它单独跑 26 秒通过、在全量里被挤到超时。同一个坑还牵出一条**会让整组界面用例静默跳过**的本机环境问题
   （Tcl 8.6.12 与 8.6.15 混用），也已修好。

**登录读不到 `userhash` 的问题仍然开着**，这一版与它无关。下一步按评审 §8.4 做的是「逐扇页面目标各自读罐 +
罐指纹变化就重读 + 详单落盘」；等你下次真机复验时，把「读罐对账」整行（以及需要的话那份「读罐详单」）贴回来。

- 全量用例 **1853 passed / 7 skipped**（收集 1860 项）；
- 契约用例（文档事实、版本号一致、使用说明分段、文本卫生、打包清单）全绿；
