# v0.19.3：备用推送工具改走本地 git 图，不再整条重建历史

这一版**不改任何用户能看到的行为**——只改仓库里的发版工具。

## 为什么

git push 走不通时，发版靠 	ools/push_via_api.py 经 GitHub API 逐对象上传。
它判断「哪些提交已经推过」的旧办法是：取远端最近 100 条提交，再与本地逐条比对。
本地历史一旦超过 100 条，本地第 1 个提交就永远不在这个窗口里，比对结果恒为 0 ——
于是每次推送都当成「一条都没推过」，重建全部提交、重传一千多个 blob
（2026-10-25 实测：1360 个 blob，耗掉一个多小时）。

## 这一版做了什么

- 先用**本地 git 图**算：git rev-list --count <远端顶端>..HEAD。
  零网络请求，也完全不受历史长度影响。
- 本地缺远端对象（刚在网页上改过历史、或换了机器）时才走接口：
  先在本地定位「远端顶端对应哪一条」，再抽检最近 VERIFY_DEPTH = 4 条父链确认
  没被改写；对不上就只认对上那一段。
- 实测同一场景：**485 秒 → 0.0 秒**（远端顶端就是本地 HEAD）／**3.1 秒**
  （本地多一条待推），API 请求从 200 多次降到不超过 5 次。
