# v0.13.40：浏览器「起来就退」时，把它自己写的最后几行话带出来

## 该下哪个附件

下载 **免安装包** `xdao-export-v0.13.40-win64.zip`（解压后双击 `xdao-export.exe`，不需要装
Python）。同一页还挂着一份 `xdao-export-v0.13.40-win64.zip.sha256` —— 那是给上面这个包核对
用的校验文件，不是程序，不用解压。

## 这一版改什么

这一版只做一件事：**让「浏览器起不来」这件事有个当事人在场**。

在此之前，程序启动浏览器时把它的 `stderr`（标准错误输出，浏览器往里写「我为什么不干了」）
直接丢掉了（重定向到 `DEVNULL`）。于是用户能看到的只有程序自己猜的几句：

```
Edge 刚起来就退出了（退出码 21）。资料目录里的旧状态坏掉、或者被安全软件拦下时会这样；
程序会换一个干净目录、必要时再换一个浏览器重试。
```

这几句是**推测**。真机上「起不来」的原因五花八门 —— 资料目录被另一个进程锁着、安全软件
拦下了远程调试端口、启动参数被策略拒绝、可执行文件所在目录不可读 —— 浏览器其实把真正的原因
写在了 stderr 上，而我们把它扔了，用户和排查的人都只能在一堆猜测里挑。

这一版改成：

- **写进一个临时日志**：启动前在 `%TEMP%` 建一个 `xdao-browser-stderr-<进程号>-<纳秒>.log`，
  把浏览器的 stderr 接到它上面（不再丢进黑洞）。
- **失败时把尾巴带出来**：启动失败（进程自己退了、或者等到超时）时，取日志**最后 5 行、
  最多 600 字**，接在原来的错误话后面：

  ```
  …（浏览器自己最后几行话：ERROR: could not create the profile directory / ERROR: profile is locked by another process）
  ```

- **成功即删、失败也删**：端口等到了就把日志删掉；每次失败读完也删。正常使用不会在 `%TEMP%`
  里攒垃圾（日志名字故意不带资料目录那两个前缀，不会被清扫逻辑当资料目录处理）。
- **日志建不出来也照常干活**：临时目录写不进去（安全软件不让写）时，就退回原来的「没有这几行
  话」，绝不因为少一份日志让浏览器起不来。

**真机验证**（2026-10-04）：用真的 Edge 起一扇窗，在日志被删掉之前把它读出来，里面正有 Chromium
自己写的一行 `DevTools listening on ws://127.0.0.1:54815/devtools/browser/838e302b-…` —— 这一行
以前就是被丢进黑洞的。再在同一份**还开着**的资料目录上启动一次，报出来的仍然是「退出码 0 + 就
有一扇窗开着」那段：这一次浏览器没往 stderr 写东西，提示里也就没有多出一段空的「浏览器自己最后
几行话」（空的不加，不加噪音）。

运行时看日志的界面、导出格式、配置文件、命令行开关都没动 —— 变的只是出错时那几句提示里
多了一段**浏览器的原话**。

## 登录不行的话，这一版怎么自救

1. 这一版**不修**登录本身，修的是「登录起不来时你看不清为什么」。所以：再遇到「浏览器起不来」，
   先把对话框里那段「浏览器自己最后几行话」抄下来（或截图），它通常一眼就能说明白是锁住了、
   被拦了、还是别的。
2. 想回到全新状态：关掉所有程序开的登录窗口，再把 `%APPDATA%\xdao-export\browser-profile`
   文件夹删掉，重新点「用浏览器登录」。
3. 急用不等程序抓：在你登录成功、刷新都不弹回登录页的那扇窗里按 F12 →「应用程序/存储」→
   Cookie，抄出 `userhash=…`，用主界面的「直接粘贴饼干登录」贴进去。

## 下载后核对一下

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.40-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.40-win64.zip.sha256
```

两行的字符串一样就是原件。
