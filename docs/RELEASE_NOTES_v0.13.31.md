# v0.13.31：你关标签不算事，登录慢也不催了

## 该下哪个附件

下载 **免安装包** `xdao-export-v0.13.31-win64.zip`（解压后双击 `xdao-export.exe`，不需要装
Python）。同一页还挂着一份 `xdao-export-v0.13.31-win64.zip.sha256` —— 那是给上面这个包核对
用的校验文件，不是程序，不用解压。

## 这一版修了什么

上一版（0.13.30）修的是「领饼干被弹回登录页」，真机复验又暴露了三处更基础的毛病，这一版
一起修掉：

- **每轮读之前重挑标签页**。以前程序在浏览器启动那一刻挂上哪个标签，之后就一路只盯它 ——
  你把那个标签关掉、另开一个去登录（很多人就是这么干的），程序就对着已经死掉的旧标签一路
  报「页面停在登录页」，新标签里登录得再成功它也不看。现在每轮重新数一遍标签：有 X 岛页面
  就挂到它上面；没有站点页、手头连接又还活着，就按兵不动，绝不把用户正停着的页面换来换去。
- **读浏览器失手一下不再当场撒手**。关标签、重开页面的那一下，调试连接常会断一下；以前
  任何一次异常都直接报「读取浏览器饼干失败」结束战斗。现在下一轮会自己重连，连续四轮都读
  不动才认输报错。
- **到点了自动续等**。等登录的时间预算原来是 5 分钟，到点就宣布超时 —— 可有人就是登录慢
  一点（收验证码、翻密码管理器）。现在只要浏览器窗口还开着，到点自动续一轮，最多续三轮
  （一共约二十分钟）；超时那句里的分钟数也照实际等待时间写，不再谎报。

另外修了一处**冤案**：程序拿到新饼干后会先验一次「这块算不算数」，以前这一问用的是程序
自己写死的旧身份（UA），站点认出跟浏览器不是同一个客户端，把验证请求弹回登录页 —— 于是
你刚点完「应用」、明明好用的新饼干，被错报成「浏览器里那块 userhash 饼干 X 岛不认（多半
是上一次登录留下的旧饼干）」。现在验证之前会先把程序这张嘴换成浏览器自己的长相再问。

## 为什么小版本号排到 31 了（版本号规矩）

`0.13.x` 不是把一个小功能拆了 31 次，而是**「用浏览器登录」这条功能线的一次真机反馈修一
版**：0.x 的规矩是「0.12 起加新版本检查、0.13 起加浏览器登录……」，同一功能线上的连续修
Bug 只动最后一位。这条线反馈特别密集（每次都是真机上才会露头的毛病），所以 0.13.x 排得
长。下条新功能线开始会是 0.14.0；等功能和用户都稳定了，才会进 1.0。

## 还是登不上怎么办（这两招现在都好用）

1. 在程序开出来的那个浏览器窗口里，手动打开
   `https://www.nmbxd1.com/Member/User/Cookie/index.html`，对任意一块饼干点「应用」——
   userhash 当场进罐，程序下一次张望（30 秒内）就会自己把它捡回来；
2. 或者在你自己常用的浏览器里登录 X 岛，按 F12 → Application → Cookies 找到 `userhash`
   那一行复制值，用「登录 / 设置饼干」里的「直接粘贴饼干登录」贴进去。

把 zip 和 `.sha256` 放同一个文件夹，在 PowerShell 里：

```powershell
Get-FileHash .\xdao-export-v0.13.31-win64.zip -Algorithm SHA256
Get-Content .\xdao-export-v0.13.31-win64.zip.sha256
```

两行的字符串一样就是原件。
