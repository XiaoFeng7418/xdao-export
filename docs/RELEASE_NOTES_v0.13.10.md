# v0.13.10：临时资料目录，起不来的那次也会收掉

这一版只修一个收尾问题，跟怎么用没关系。

## 现象

从 v0.13.9 起，「用浏览器登录」每次开一个**全新的临时资料目录**（系统临时目录下），
登录窗口关掉后自动删掉。可**删得不全**：浏览器「一起来就退出」的那些次，目录已经建出来、
里面也落了文件，却没人去删。一连失败几次，系统临时目录里就攒一堆空壳
（这台机器上量到 147 个 `xdao-export-browser-profile-*`，其中 123 个是空的或只有一两个文件）。

## 原因

第一层：v0.13.9 只在**成功用上**临时目录这一步记了个记号（`_fresh_used`），收尾时按这个记号
决定删不删。于是两条失败路径都没人删：

1. 换目录重试全都没起来（浏览器一起来就退）；
2. `Popen` 本身就抛错（比如找不到浏览器可执行文件）—— 这条**不经过** `start()` 的换目录重试分支，
   连 `stop()` 都不会被调到。

补完第一层，真机复量**还剩目录**，才挖出第二层（更隐蔽）：

3. `start()` 的候选表只在浏览器循环**外面**算一次。第一个浏览器把临时目录试败、目录当场删掉，
   换到下一个浏览器时第一个候选**还是那个路径**，`_launch` 里的 `mkdir` 又把它建出来 ——
   可这时 `temp_profile` 已经清成 `None`，那一份就永远没人管（真机上量到的空目录就是它）。
4. 备用候选里有一个建在**系统临时目录**下（`%TEMP%\xdao-export-browser-profile-<pid>`，
   见 `fallback_profile_dirs()`），它从来没被记账：每次失败都会把它新建一遍、然后留着。

## 改法

- 只要这次**动手建过**临时目录，就一定会收：`_fresh_candidate()` 拿到名字时就记进清单，
  收尾时无条件调用 `cleanup_temp_profile()`（它自己会判断有没有目录）。
- **清单只增不减**（`self._temp_dirs`）：删过的路径也留着 —— 真机上出现过「删掉之后又被
  下一次尝试建出来」，删一次就把路径忘掉的话，那一个就没人管了。
- **每个浏览器各拿一个新的**临时目录：候选表挪进浏览器循环，不再共用一份。
- **建在系统临时目录下的候选都算程序自己建的**（判据 `_is_temp_profile_dir()`：位置在系统
  临时目录 + 名字前缀 `xdao-export-browser-profile`），收尾一并删。
- `_launch()` 里 `Popen` 抛 `OSError` 时当场收一次；`start()` 最后报错前再兜底收一次。
- 用户配置目录里的备用目录、你自己开着的浏览器，一律不动。

## 顺带量到的两条（都不是缺陷）

- 打包版的登录这条路本身是好的：把真的 `LoginBrowser` 打进冻结 exe 跑，两次都起来
  （0.5~0.6 秒、调试端口答得上话、目录里 160~170 个文件、`stop()` 后临时目录已删）。
- 之前怀疑的「冻结进程里起的 Edge 一起来就退（退出码 21）」是那个极简探针 exe 的假象，
  跟产品无关。
