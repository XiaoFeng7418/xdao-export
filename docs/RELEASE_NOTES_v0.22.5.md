# v0.22.5：把「用浏览器登录」的兜底分支都钉进用例

功能与 v0.22.4 完全一样，产物也一样。这一版只补测试：不改任何能看到的行为，
也不动命令行开关、配置项与文件名模板。

## 为什么

「用浏览器登录」点下去之后，后台要做一长串事：找浏览器、起进程、连调试端口、
找页面、读饼干、换资料目录、收尾杀进程。主干路径早有用例，但这些事**出错时**
走的分支基本没人测：

- 饼干读不到（罐被别的进程占着、页面正在换地址）；
- 资料目录换不了名（同名目录已经存在、权限不够）；
- 调试端口文件里写的是垃圾（上次被杀留下的半截文件）；
- 进程表查不到东西（PowerShell 起不来、输出编码不对）；
- 窗口连上了又立刻断（用户手动关掉、浏览器自己崩了）。

这些分支平时不走；一旦走了就是最需要日志的时候，也最容易改坏。补用例的目的
是：以后谁再动这段代码，改坏了会当场有人喊停。

## 这版做了什么

`tests/test_browser_login.py` 358 → **420** 条，新增 62 条（全部用替身，不开窗口、
不起进程、不联网）。挑几类说：

- **进程与目录**：进程表普查认出自家资料目录、关掉普查时立刻早退、目录改名失败时
  不抛、端口文件内容损坏时当作「查不到」继续扫、刚起来的窗口不去动它、
  删不掉时留在 kept 里、三次重试后才放弃。
- **找浏览器**：环境变量名大小写不敏感、同一路径只认一次、命令行只有引号没有内容、
  带后缀的名字（`chrome-beta.exe`）也认得、默认浏览器的 ProgId 是空值或命令行不带
  引号时的两种回落、默认浏览器不在候选表里时照旧列出其它浏览器。
- **读饼干**：罐读失败回空、窗口连上又立刻断、只有一份罐、某份上下文读失败时跳过、
  页面里读不到地址、跳转页 fetch 失败、饼干列表只有表格没有链接、全都没值时给一句
  能照着做的话。
- **一条老用例的时好时坏**：`test_navigate_keeps_polling_through_a_document_swap`
  原来靠 50 毫秒的超时结束循环，满负载跑全量时会空手返回（真红过一次）。改成靠
  「加载完成」退出，与机器快慢无关。

## 读数

- `xdao/browser_login.py` 行覆盖：93% → **99%**（1711 条语句，未覆盖 124 行 → 9 行）。
  剩下 9 行是几条「要么根本到不了、要么要真跑五秒以上」的兜底，判定不划算，留着。
- 测试：2881 项，本机 2874 通过、7 项真机用例默认跳过。
- 自动检查：构建 / 主干测试 / 标签测试三条 run 全绿。
