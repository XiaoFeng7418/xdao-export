# v0.21.12：给界面上几处「不好走到」的分支补用例

这一版不改任何用户能看到的行为——只补测试。上一版把「后台线程里那一小段」的成功与失败两条路钉住了，这一版继续往外扩：对话框的取消与报错、导出与监控的早退、登录窗口主线程轮询的兜底。

## 为什么

界面代码的麻烦不在主路径，而在「用户手滑一下 / 系统不给面子」的那些分支：保存框点了取消、导入的清单里全是坏条目、桌面通知发不出去、窗口比消息先关掉。这些路以前多半靠手点试出来，出问题又难复现。把它们写成用例，以后改动就不会悄悄改坏。

## 这版做了什么

新增 32 条用例（`tests/test_gui_entry.py` 160 → 178、`tests/test_window.py` 116 → 123、`tests/test_gui_browser_login.py` 79 → 86）：

- 监控窗口：输入框空着点添加、一锅乱炖贴网址（认不出的与重复的都跳过）、保存框取消、写文件失败、导入跳过超过 10 条时的截断、导入空清单。
- 编辑监控：「指定饼干」没填就选它、页数填成负数，都当场说清且不保存。
- 设置窗口：超时与重试填非数字回落默认值；缓存目录与浏览器可执行文件的选择框点取消时保留原值。
- 导出与监控的早退：没登录、没填网址、串号截止把列表全挡住、导出目录没准备好、监控已经在跑、系统发不出桌面通知、监控循环自己抛异常。
- 登录窗口主线程轮询：饼干取到了却装不进客户端、窗口先被关掉、写运行日志本身失败、改按钮文案时窗口已销毁。
- 更新提示：能原地升级时问一句、不能时把原因写进日志、没有下载地址时只记一句。

做法上，能真开窗口的用真 Tk；不能的用 `object.__new__` 造个只带用得到的属性的半成品，`messagebox` 与 `filedialog` 全部换成记录器——不开对话框、不联网、不弹窗。
