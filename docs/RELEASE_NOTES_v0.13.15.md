# v0.13.15：登录成功了，程序为什么一直没反应

## 现象

在「用浏览器登录」打开的窗口里登录成功、页面已经进了用户界面，程序却一直停在「浏览器已经
打开了：请在里面登录 X 岛用户系统。登录成功后这里会自动关掉。」——既不关窗，也不报错。等满
5 分钟才蹦出一句超时提示，看起来像卡死。（v0.13.13 及更早版本都有这个问题。）

## 原因

X 岛登录成功后**不会**直接下发 userhash 饼干：还要去「饼干」那一页应用一块，主站才会设置它。
程序原来的做法是在**当前打开的那一页**的 DOM 里找「应用」链接（`Cookie/switchTo/id/<id>.html`）——
登录后页面往往已经跳到论坛或用户首页，那里没有这种链接，于是每 5 秒试一次、每次都拿不到，
一直到超时。界面在这期间一句话都不说，就成了「没反应」。

## 改法

- 当前页面里找不到「应用」链接时，程序自己去请求一次 `.../Member/User/Cookie/index.html`，从取回
  的 HTML 里接着找（同源请求，带的就是浏览器里的登录会话）；停在哪个页面都取得到。匿名访问那
  一页时拿回的是站点自己的「跳转提示」页，里面没有链接，所以不会被误判成「已登录」。
- 请求统一加 8 秒超时（`AbortController`），免得某一页卡住时整个等待没了动静。
- 等待期间状态栏每 15 秒写一句：「已经等了 N 秒，还没在浏览器里看到登录。要在这个窗口打开的那个
  浏览器里登录，程序才看得到；登录成功后这里会自己关掉。」
- 5 分钟超时的那句话补上：在自己平时用的浏览器里登录，程序看不到 —— 可以点「直接粘贴饼干登录」。

功能、界面布局、导出结果与 0.13.14 完全一致。

## 真机核验

- 取饼干这条链（真 Edge + 临时资料目录 + 真 CDP）：改动前的脚本在「已经登录、但页面不是饼干
  列表」时返回空（复现现象），改动后取到饼干；把真实的匿名「跳转提示」页喂进去仍然返回空；
  当前页本身就是列表时不多发请求。9 项检查全过。
- 界面这一层（真 Tk 窗口 + 真浏览器）：等待期间状态栏确实报过时长，登录后窗口自己关掉、
  userhash 写进客户端、成功前问过服务端这块饼干。6 项检查全过。
- 收尾：临时资料目录删干净，`%TEMP%` 里没有残留，没有留下浏览器进程。
