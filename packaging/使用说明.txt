怎么运行
--------
双击 **xdao-export.exe** 即可，不需要安装 Python，也不需要安装任何依赖。

请不要把 xdao-export.exe 单独拷走 —— 它旁边的 **_internal** 文件夹是它的运行库，
两个必须放在一起。要挪位置就整个文件夹一起挪，或整个文件夹一起压缩。


发布形式
--------
本版**只提供这个免安装版（zip）**，不再提供"单文件版"。
单文件版的启动器会先把内容解压到系统临时目录，只要解压出来的路径里带中文
（例如 D:\某中文目录\…），或者临时目录不可写，它就会在程序真正启动之前弹出
「Could not create temporary directory!」，根本打不开 —— 这取决于你把文件放在哪儿，
程序自己兜不住。这个文件夹版**不做任何解压**，直接原地运行，中文目录下也能正常启动。


首次使用
--------
1. 双击 xdao-export.exe 打开界面；
2. 点右上角「登录 / 设置饼干」登录 X 岛账号（推荐用「用浏览器登录」，见下一节）；
3. 把串网址粘进输入框（每行一个），选抓取范围与导出格式；
4. 选好导出目录，点「开始导出」。

不登录也能用，但只能读到每个串的前 100 页。

想确认程序本身是否正常，可以在本文件夹开命令行运行：
    xdao-export.exe --selftest
它会先查本机（配置目录、缓存目录、导出目录、浏览器、导出格式），再测接口能不能通；
每项给「可以 / 注意 / 不行」三种结论，返回 0 表示全部就绪。
只看本机不联网就加 `--offline`；想把结果贴给别人看就加 `--selftest-json`（JSON 输出）。
界面里也有同一个入口：「运行日志」右上角的「自检」按钮，结果能一键复制。


登录：不用再碰开发者工具（v0.7.0 起）
------------------------------------
点「登录 / 设置饼干」→「用浏览器登录」，会弹出一个**独立的小浏览器窗口**，
已经在 X 岛登录页上：

1. 就在这个窗口里像平常一样登录（账号密码 + 验证码，浏览器也能帮你填密码）。
   认准窗口：程序看的那个，顶上钉着一条**棕色横条**「串导出程序正在看这个窗口」，
   横条末尾带**【窗口号 XXXX】**，登录对话框里报的是同一个号 —— 号对上的那扇窗才是
   程序的窗；号对不上、或根本没有横条的窗口，登了也白登（横条每轮重钉并刷新文字，
   页面跳转了也不会掉，旧窗口残留的横幅也会被改成新号）。
2. 登录成功，站点就**自动带上你当前的饼干**（那一刻浏览器里已经有 `userhash` 了），
   程序自己会拿到 —— 不用先点「应用」。十几秒还没拿到，就到「我的饼干」列表里
   点一行「应用」（站点会显示「饼干切换成功」）；要**换一块**饼干也是这一步。
   （以前这里写着「光登录不算完、必须点应用」—— 写错了，v0.13.33 真机复验证伪：
   登录就有饼干，程序抓不到是程序自己读罐的锅，v0.13.34 已修并加了自查。）
3. 回到主界面，日志里会写「登录成功，饼干已保存」。

这条路的好处是：不用按 F12、不用在一堆 cookie 里找 `userhash`、不用手抄。
窗口用的是程序自己的临时数据目录，**不会动你平时那个浏览器**的登录状态和书签；
调试端口只监听本机（127.0.0.1），关窗即回收。
v0.13.33 起：再点「用浏览器登录」时，如果之前程序开的窗口还活着，会**直接接上那个
窗口**、不再另开一个新的 —— 程序窗口全世界只留一个，看得见的饼干罐子也就只有一罐；
接上旧窗口时，日志会写明「接到之前开着的程序窗口上了」。
v0.13.35 起：开窗前程序先做一次**普查**，结果写进运行日志 ——「开窗前普查：探到 N 扇
还活着的程序窗口…接手了「××」这一扇」或「没探到…这次是全新开的一扇」。到底有没有
复用旧窗口、复用的是哪一罐饼干（对账行的「罐=」就是它的目录名），日志里一目了然。
v0.13.36 起：程序重挑标签改成**钉稳** —— 挂着的是活着的非登录页页面就不再换页，
只有挂在了登录页上、而浏览器里另有站点页时才挪过去一次；不再两页之间来回跳。
v0.13.37 起：普查再加一手**进程侧点名** —— 端口文件被哪一轮预删了、备用目录的名字
又带着当时进程的编号（本轮程序猜不到），旧窗口就会彻底隐形：你看得见它、程序接不上它，
于是照旧新开一扇，两扇窗各拿各的饼干罐。现在程序在开窗前直接列出还在跑的浏览器进程、
认领**只属于程序自己**的资料目录（你平时上网的浏览器从头到尾不沾）：端口还答话的旧窗
照常接上；端口失联的僵尸窗**先收掉**，普查句会点名「进程侧探到 N 扇端口失联的旧窗口
（××），已先收掉」。程序落在自己存的持久资料目录时也会明说：那份目录记得上次开窗口时
打开过的页面，你在窗口里看到旧的「饼干列表」就是这么来的，跟你的浏览器无关；想回到
全新状态，关掉所有程序开的登录窗口后把这个文件夹删掉即可（只动程序自己那份）。
（v0.13.23 起，这个窗口只负责让你把验证码认过去：登录成功后程序读一次窗口里的整罐
饼干，接下来由程序自己去站点领饼干，**一个标签页都不动** —— 它停在哪个页面、站点那张
「跳转提示」页的倒计时跑到第几秒，都不影响结果。拿不到饼干时，界面那行提示与超时那句话
会写明窗口里有哪些饼干、走 HTTP 那条路时站点说的原话；v0.13.34 起，运行日志还会
补打一行「读罐对账：…——」，把程序会用的每种读法各自看到了哪些饼干名并排列出来
（**只有名字，绝不写值**），哪一路读漏了一眼就能看出来。v0.13.35 起这行还会报罐：
「罐=这扇窗的饼干目录名｜全罐=N｜原始userhash=…」—— 连**域名不对或被分区（CHIPS）
挡掉**的 userhash 都会被点名，一行就能定性是「读错了窗口」还是「域/分区被过滤」。
v0.13.36 起这行再多一段「页=N（这页地址｜那页地址…）」：浏览器此刻开着哪几页、
各挂在哪个地址，一行看全 —— 僵尸标签（页面早没了、记录还挂着）藏不住（只写地址，
照旧绝不写任何饼干值）。
v0.13.37 起再多一段「接=端口N」——程序这一趟接的是哪一扇窗（调试端口号）同并报出，
两扇窗的罐目录同名也一眼分开（照旧只有名字和号码，绝不写值）。
把这行截图发给维护者即可定位。）

- 支持的浏览器：Edge（Windows 自带）、Chrome、Chromium、Brave，按这个顺序自动找。
- **Firefox 用不了这条路**：它跟上面这些不是同一套内核，程序取饼干的接口（Chromium
  的调试协议）在它上面不存在。机器上只有 Firefox 时，界面会直接说明，并让你改走下面那条路。
- 机器上没装这些浏览器时不会变砖：界面会告诉你，并让你改走下面那条路。
- 窗口开太久没登录会自动超时，点「重新打开浏览器」即可。

不想开浏览器，就点「**直接粘贴饼干登录**」：在你自己浏览器里登录 X 岛用户系统后，
把 cookie **整段**复制粘贴进对话框就行（`userhash=...` 也在这段里），程序会自己把值摘出来。
粘贴内容里找不到 userhash 时会提示你，不会静默失败。


功能速览
--------
- 五种格式：HTML（单文件）、TXT、Markdown、EPUB（电子书）、PDF；
  **打包版也能导出 PDF 了**（v0.10.0 起，纸张 / 页边距 / 缩放 / 页码范围都能设）；
  浏览器真的起不来时（没装、路径不对、被安全软件拦下）会自动改存 HTML 并说明原因。
  图片可以选内嵌、只存链接、或者干脆丢掉（主界面「图片」下拉框，HTML / PDF / EPUB 都认，
  命令行是 `--image-mode embed|url|drop`）。
- 断点续传：抓过的页会缓存，中断后再跑只补缺的页；长串第二次导出通常只花一次请求；
  缓存目录默认是「导出目录下的 .cache」，想固定到别处可以在「设置」里改，命令行是 `--cache-dir 目录`；
- 图片缓存：同一张图只下载一次；
- 导出随时能停（v0.17.0 起）：导出途中「开始导出」会变成「取消导出」，点一下就停，
  已经导出的文件都留着；
- 只看指定饼干：可以从当前串第一页里勾选要保留的发言人；
- 导出范围（v0.14.0 起）：**最多页数**（留空或 0 = 不限）与**串号截止** —— 抓到该串号为止，
  **含它本身**，它后面的串跳过；命令行是 `--max-pages N` 与 `--until <串号>`。
- 正文字号（v0.15.0 起）：导出成品的正文磅数，设置里选 10~28（默认 14），
  命令行是 `--font-size 20`；只影响 HTML / PDF / EPUB（TXT 与 Markdown 是纯文本，没有字号）。
- 批量断点续跑（v0.18.0 起）：设置里勾上「成品已存在就跳过」
  （命令行 `--skip-existing`），重跑时同名成品非空的串跳过，只补没导完的。
- 图片处理（v0.16.0 起）：HTML / PDF / EPUB 都认「图片」下拉框（内嵌图片 / 仅保留链接 /
  丢弃图片），命令行是 `--image-mode embed|url|drop`；选「仅保留链接」就不下载图片了，
  文件小很多、导出也更快。
- 图片存到同名目录（v0.19.0 起；v0.20.0 起 Markdown 也支持）：`--image-mode folder`
  （界面下拉选「存到同名目录」）把图片写进成品旁边的 `<成品名>.files/` 目录，正文用
  相对路径引用；发给别人时把成品与 `.files` 目录一起带上。PDF 与 EPUB 选它会按内嵌
  处理。
- 串号清单文件（v0.20.0 起）：要导的串写进一个文本文件（一行一个串号或网址，空行与
  `#` 开头的行忽略），命令行 `--input 清单.txt`，界面里点输入框右边的「从文件…」。
  同一串号只导一次、按文件里的顺序；有认不出的行会指出行号并整体拒绝。
- 合并导出（v0.21.0 起，可选、默认关闭）：设置里勾上「把这次导出的串合并成一个文件」
  （命令行 `--merge`），这次导的串就写进同一份 HTML / TXT / Markdown / PDF；不勾就是
  老样子，一个串一份文件。EPUB 不支持合并（它是单个 zip），选了会自动按一个串一份存。
- 文件名模板：{title} {id} {date} {po} {count}；
- 校验老楼层是否被编辑过：命令行 `--verify`（界面在「串监控」窗口里勾），
  发现改动过的楼层就重新导出，代价是每轮多一次请求；
- 串监控：盯住若干串，定时检查新回复并自动导出；监控列表能导出成文件、换机器之后导回来（v0.9.0 起）；
- 每条监控可以各自限页数（v0.16.0 起）：加进列表时记住当时的「最多页数」（0＝不限），
  监控表「范围」列会写明「最多 N 页」；
- 监控条目能原地改（v0.17.0 起）：选中一行点「编辑选中」（或双击那一行）就能改范围、
  格式、图片处理与最多页数；串号本身不给改，换串请移除后重加；
- 导出 PDF 失败时可以用命令行 `--pdfdiag` 自查：它会说明浏览器能不能启动、带了哪些参数；
- 界面配色：右上角「配色」下拉框可切浅色 / 深色，选完记住；
- 界面字号：右上角「字号」下拉框可把整个界面调大调小（小 / 标准 / 大 / 更大 / 特大，
  0.85~1.5 倍），窗口与左栏跟着一起变，选完记住；
- 缺页自动补抓：某一页没抓下来不再中断整趟，补不上会告诉你缺了第几页；
- 设置里可配代理、请求间隔与超时；被限流（429）会自动退避重试。


导出目录写不进去怎么办
----------------------
v0.5.0 曾在开始抓取前往导出目录写一个探针文件 `.xdao-write-probe`，写不进去就直接
拒绝导出。问题是**探针文件写不进去，不等于导出结果写不进去** —— 安全软件、只读策略
可能只挡这一个点开头的文件，结果就是老版本（0.1.0）能导出的目录被新版自己拦下。

v0.5.1 起：

- 探针改成和导出结果同类的普通文件 `xdao-write-test.tmp`（写完立刻删掉），
  探针的结论才跟真实导出对得上；
- 即使探针仍然失败，它**只做预警、不再拦路**，程序照常抓取、照常写结果文件；
- 真的写不进去时，报的是**真实文件名 + 真实原因**，例如：

      [Errno 13] Permission denied: 'D:\某目录\串12345678.txt'

遇到这种情况，换一个当前账户可写的目录，或在文件夹「属性 → 安全」里给当前账户
「完全控制」权限。只有当目录**连创建都做不到**时，程序才会在抓取前提示
「导出目录不可用」。

v0.5.2 起，判断"这个目录能不能写"会**往下探一层**：既试建一个探针文件，也试建一个
临时子目录（真实的缓存/导出都会在自己下面建子目录）。探完立刻删干净，不留垃圾。
这么改是因为出现过 `<盘符>\X岛\.cache` 建得出来、`<盘符>\X岛\.cache\pages` 却拒绝访问的情况 ——
只探表层会把这种目录误判成"能写"，于是"写不进去就换个地方"的兜底永远不触发。

如果换了目录仍然提示"拒绝访问"，说明目标位置确实不允许当前账户写。这时请运行本文件夹里的

    诊断写入.ps1

（右键 → 使用 PowerShell 运行）。它会打印每个候选目录能不能写、目录的权限表、
以及 Windows「受控文件夹访问」的状态，把结果发给维护者即可定位。

**v0.5.3 起，导出目录写不进去时程序会自己换个能写的地方**，不用你手动改设置：

- 优先换到 `%LOCALAPPDATA%\xdao-export\导出`，其次 `%TEMP%\xdao-export`；换之前会
  真的试写一次，确认能写才用；已经存在同名目录时会用「导出-2」「导出-3」，
  不会盖掉上一次的成品；
- 换地方会同时弹提示 + 写日志，导出目录那一栏也显示新位置，但**不改你的设置** ——
  下次启动仍按你设的位置试；
- 你在「更改…」里亲手选过导出目录之后，程序只报错、不再擅自换地方（命令行 `-o` 同理）。

这么做是因为「写不进去」按实测有三类成因（2026-10-11 定案，按常见程度排）：

1. **程序是从一个「被限制写入的目录」里启动的**（沙箱、受限令牌这类环境）。这一条最容易
   被当成权限问题：程序能启动、能读，可往 `%APPDATA%`、桌面/文档、甚至别的盘写都是
   `[Errno 13] Permission denied`，而同机器上别的程序（记事本、PowerShell）写同样的目录
   却没事。**把程序整个文件夹挪到一个不受限的位置即可**（实测同一个包在受限目录里自检报
   两处「不行」，挪出来全部正常）。
2. **Windows 的「受控文件夹访问」（勒索软件防护）**：它默认保护**桌面、文档、图片、视频**，
   没进白名单的程序一律不许往那里写文件。想让程序直接写进桌面或文档：

       Windows 安全中心 → 病毒和威胁防护 → 勒索软件防护 → 受控文件夹访问
       → 允许应用通过 → 把 xdao-export.exe 加进去

   注意：这个开关处于关闭状态（受控文件夹访问 = 0）时，第 1 类成因照样会拦。
3. **第三方安全软件的「文件保护 / 重要文件保护」**：火绒、360、电脑管家这一类会按「程序有
   没有签名」判定，没签名的程序往用户目录写会被静默拒绝。注意它们的**「信任区」通常只管
   病毒查杀**（火绒的信任区页自己写着「病毒查杀与病毒防护的扫描功能将跳过以下信任项」），
   要放行写入得在「防护中心 → 系统防护 → 文件保护」里加白，或把程序目录加进去。

怎么一眼分清是哪一类：双击本文件夹里的 **诊断写入-双击运行.cmd**，它测的是 **PowerShell
进程**能不能写这些目录 —— 报告里桌面/文档是「写不进去」而 `%LOCALAPPDATA%` 是「能写」，
就是第 2 类；报告里**全是「能写」而程序自己仍写不进去**，就是第 1 或第 3 类，跟目录权限、
跟受控文件夹访问都无关。

**诊断脚本现在会把结果存成文件**：以前双击运行窗口一闪就没了、什么也看不到。现在跑完会
把完整报告写成 `诊断结果-年月日-时分秒.txt`（优先放在脚本旁边），并打印「已保存：<路径>」，
最后等你按回车才关闭。不想记命令的，直接双击本文件夹里的 **诊断写入-双击运行.cmd** 就行。


抓长串时少了一页怎么办（v0.6.0 起）
------------------------------------
以前只要某一页没抓下来（网络抖动、超时、被限流），程序会**从这一页直接停住**：
后面的页一页都不再试，产物少一大截，界面和日志却一句都不提。

v0.6.0 起：

- 某一页失败只是先记下来，**后面的页照抓**；第一遍跑完再对失败页统一补抓
  （默认补 2 轮，每轮之间等一小会儿，避免同时失败多页时被接口限流）；
- 补上了：日志写「有 N 页第一次没抓下来，补抓成功。」；
- 补不上：明确写出**缺了第几页、补了几次、最近一次失败原因**，并提示
  「再导一次通常就能补齐」—— 已经抓下来的页都在缓存里，重跑只补缺的那几页；
- 只在"试过的页一半以上都失败"时（多半是断网或限流），才会把**连试都没试**的
  尾页也算进缺失，免得你以为只差一两页；
- 抓取范围撞到页数上限时，会说明"这次只抓到第 N 页（串比这长）"，
  并提示可以用「抓取范围 → 指定页码」分批导出；
- 界面在这时另外弹一次「有串没抓全」，日志里逐条列出是哪些串。

顺带修掉一个会让缺页永远补不上的问题：缓存里"抓到第几页"以前记的是最大页号，
中间缺页时仍会声称缓存完整，下一次导出就直接复用了缺页的缓存。


界面配色（v0.6.0 起）
--------------------
右上角多了「配色」下拉框，可以随时在**浅色 / 深色**之间切换：

- 选完立刻生效，并且**记住**，下次启动还是这个配色；
- 切换时日志内容和你已经填好的串地址都不会丢；
- 正在导出或监控时不允许切换（切换会重建界面，免得打断进行中的任务）。


监控列表的备份 / 还原（v0.9.0 起）
----------------------------------
「串监控」窗口的列表下面多了两个按钮：

- **导出列表**：把当前监控的串存成一个文件（默认文件名带日期，例如
  `xdao-export-监控列表-20261001.json`）。列表为空时不弹保存框，直接提示。
- **导入列表**：选一个文件导回来，**合并进现有列表**，不会冲掉原有的条目。
  文件里认不出的条目会逐条说明原因（例如「格式认不出：docx」），能认的照常导入 ——
  坏一条不会毁掉整份文件。

换机器、重装系统之后，装好新版再「导入列表」就能把监控的串全搬过去，不用重新手输。

导出的文件是纯文本 JSON（中文不转义），你可以直接打开看、手改，或者贴给别人。
它只存「怎么监控」：串号或网址、抓取范围、导出格式、饼干筛选、图片处理方式。
**它不存「监控到哪儿了」**：上次检查时间、已导出的楼层、上次的报错这些状态跟着本机的
缓存目录走；一起搬走的话，导进来的机器会以为"这个串已经导出过了"，第一轮该出的新楼
反而不出。所以换机器之后第一轮检查会按当前进度重新核对一次。

命令行也可以：

  --watch-export 文件.json        把当前监控列表导出到文件
  --watch-import 文件.json        从文件导入（合并，不覆盖原有条目）
  --watch-import-replace          导入前先清空现有列表（要跟 --watch-import 一起用）

这两个动作不联网、也不会启动界面。参数写错会打印中文说明并以退出码 2 结束。


邮箱登录失败时，提示更准了（v0.6.1 起）
--------------------------------------
以前用邮箱登录失败，不管什么原因，弹的都是同一句
「未找到可用的饼干，请先在浏览器里登录用户系统并应用一块饼干」——
明明账号里有饼干，却让你去领饼干，把人指错了方向。

原因是 X 岛登录失败时回的不是普通网页，而是一张"跳转提示"页：它的
HTTP 状态码是 200（看着像正常响应），真正跳转靠页面里一段 JavaScript
自己完成 —— 浏览器会跟着跳，程序内部用的网络库不会。旧版本拿这张页面
当成了饼干列表去解析，一个饼干都找不到，于是报了上面那句话。

v0.6.1 起：

- 程序认得这张跳转页，会跟着它跳到该去的地方，不再当成内容页；
- 失败时会照实说，例如：
  「登录没有通过，X 岛返回：并没有权限访问，请等待自动跳转（已回到登录页）」
- 弹窗标题会告诉你属于哪一类，正文里给下一步：
  验证码不对 → 图片已经换成新的一张，重填一次；
  密码不对 → 确认密码，或用「直接粘贴饼干登录」；
  登录没有生效 → 再登一次（验证码务必用最新那张）；
  这个账号还没有饼干 → 才提示你去用户系统「饼干」页领一块。

实在登不上就点「**直接粘贴饼干登录**」，从浏览器复制整段 cookie 粘贴进来即可，
这条路一直可用（v0.7.0 起也推荐先试「用浏览器登录」）。

如果「用浏览器登录」这条路本身打不开（例如报「Edge 刚起来就退出了（退出码 21）」），
v0.13.5 起可以先用命令行问一句**浏览器到底能不能起来**：

      xdao-export.exe --check-browser

它会真的把浏览器启一次（用临时数据目录，试完立刻关掉），除了等调试端口，
还会问一句调试接口，答不上话就不算通过；挨个试的顺序就是登录时真正会用的顺序
（设置里指定的那个 → 系统默认浏览器 → Edge → Chrome …），有一个能用就停。
结论会直接说清是「可以」还是「不行」，不行时报出原因和退出码。
加 `--check-browser-json` 则输出 JSON，便于把结果贴出来。


缓存目录写不进去也不会失败
--------------------------
缓存只是加速手段，**不会因为它写不进去就让导出失败**：

- 填的缓存目录写不进去时，程序会自动换到
  `%LOCALAPPDATA%\xdao-export\.cache`（再不行换 `%APPDATA%`、系统临时目录），
  并在日志里说明换到了哪里；断点续传、图片缓存照常工作。
- 如果所有位置都写不进去，加 `--no-cache` 关掉缓存即可，导出功能完全不受影响：

      xdao-export.exe 50000001 -o D:\备份 --no-cache

- 只想先导一小段看看效果：`xdao-export.exe 50000001 --max-pages 20`；
  一串列表里只导到某个串号为止（含它）：`xdao-export.exe 50000001 12345678 --until 50000001`。
- 把导出成品的正文字号调大：`xdao-export.exe 50000001 --font-size 20`
  （只影响 HTML / PDF / EPUB；默认 14 磅）。

- 万一缓存一个字节都没留下，日志里会明确写"这次抓取不会留下断点续传的成果"，
  免得你以为下次能接着抓。


PDF 纸张 / 页边距（本版新增）
-----------------------------
以前导出的 PDF 一律按网页自己的排版来（等于浏览器的「打印」）。想要 A4、想要窄边距、
想要横版、只想导出某几页，过去只能去改网页样式。现在这些都能自己定：

- 界面：「设置」→「导出」里的「PDF 页面」——
  纸张（跟随网页样式 / A4 / A3 / A5 / Letter / Legal）、方向（纵向 / 横向）、
  页边距（跟随网页样式 / 无边距 / 窄 10mm / 普通 18mm / 宽 25mm），
  它右边一格可以填自定义边距（毫米，0～50，留空表示用左边的预设）；
  下面一行是缩放（0.5～2.0，1.0＝原始大小）与页码范围；
  再下面是「打印背景」开关（关掉就是白底，省墨）。

- 命令行：

      xdao-export.exe 50000001 -f pdf --pdf-paper a4 --pdf-margin narrow
      xdao-export.exe 50000001 -f pdf --pdf-paper a4 --pdf-orientation landscape --pdf-scale 0.8
      xdao-export.exe 50000001 -f pdf --pdf-margin 12.5 --pdf-no-background
      xdao-export.exe 50000001 -f pdf --pdf-pages 1-3,7

  `--pdf-margin` 也可以直接写毫米数（0～50，像上面第三行那样），
  等价写法是 `--pdf-margin-mm 12.5`；
  `--pdf-pages` 支持 `1-3,7`、`1-3,7-9` 这种写法；每一项的可选值 `--help` 里都列了。
  渲染一张 PDF 默认最多等 900 秒（超时也算失败，会说明原因），慢机器上可以调：`--pdf-timeout 秒`。

- **默认「跟随网页样式」**：一个选项都不填时，导出的 PDF 与以前完全一样；
  老配置（配置文件里没有这几个键）升级上来不会变样。
- 一个绕不过去的浏览器行为：**网页自己声明了 `@page { margin: … }` 时，你填的边距会被
  页面样式盖掉**（纸张同理：选了显式纸张就以你的选择为准，不再跟页面走）。本程序自己
  生成的 HTML 不声明 `@page` 边距，所以填了就会生效；万一遇到某个网页样式压过你的设置，
  把「跟随网页样式」留着当默认即可。
- 值填错时，命令行会在**开始抓取之前**停下并说明是哪一项、收到的是什么
  （例如「边距只支持 default/none/narrow/normal/wide 或 0~50 的毫米数，收到 'thin'」），
  不会跑一半才报错，也不会把错别字当成默认值悄悄咽掉；界面里填错的格子保留原来的值，
  不会写进配置。
- 命令行里给的选项优先于「设置」里存的那份；只给一部分时，其余的仍按「设置」来。


PDF 导出在打包版里也修好了（v0.10.0 起）
----------------------------------------
v0.3.0 到 v0.9.0 的免安装包有个说不出口的限制：**导不出 PDF**。选 PDF 会自己降级成 HTML，
然后提示你「在浏览器里打开它按 Ctrl+P 另存为 PDF」。要真正的 PDF，只能装 Python 从源码跑。

原因是**浏览器自己的沙箱**：Chrome / Edge 在被一个打包程序（PyInstaller 冻结进程）启动时，
沙箱初始化会失败，进程立刻以 2147483651（0x80000003）退出；同样的参数从命令行手工启动却正常。
当年排查过环境变量、工作目录、句柄继承、进程树、作业对象都没找到，就归因成了「系统级限制」。
这次逐个排除后找到了那一个开关：**--no-sandbox**。

现在：

- **打包版**启动浏览器时自动加这一个开关，PDF 正常导出，纸张 / 页边距 / 缩放 / 页码范围照旧可用；
- **「用浏览器登录」这条路同样受益**（v0.10.1 起在打包真机里单独量过）：不补这个开关时，
  浏览器进程起得来、调试端口也有，但登录页**永远加载不出来**（地址与标题一直是空的，截图报
  Internal error）；补上之后正常显示登录页。所以打包版从 v0.10.0 起，登录窗口就是能用的；
- **源码运行不加**（仍然带沙箱），行为与以前完全一样；
- 渲染的仍然是你抓下来的那个串生成的本地 HTML，不会去打开远程页面；
- 浏览器**真的**起不来时（机器上没装、路径填错、被安全软件拦下），程序照旧改存 HTML 并说明原因。

**PDF 导不出来时怎么自查**：在解压目录里开一个命令行，运行

    xdao-export.exe --pdfdiag

它会打印出：当前是不是打包运行、会给浏览器加哪些参数、本机浏览器的路径，
并用**和正式导出完全相同**的参数试渲染一次。把输出发给维护者就能定位。


配置与缓存放在哪
----------------
- 配置：%APPDATA%\xdao-export\config.json（只存登录状态与偏好，不存明文密码）
- 缓存：默认在导出目录下的 .cache；写不进去会自动换到 %LOCALAPPDATA%\xdao-export\.cache
  （也可以在「设置」里指定一个固定的缓存目录）
- 缓存可以随时在界面上清空，已导出的文件不受影响。
